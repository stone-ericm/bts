### N1 — High: edits and review identity can still be substituted without acceptance

`admission.py:111–116,137` accepts any ancestral `edits_commit` between the reviewed and exposure commits and compares HEAD to that commit. It never checks that the changes from the reviewed tree are the approved edits. An ancestry check establishes history, not verbatim application.

**Verified synthetic Git model:** report R says **SIGN WITH EDITS**, requiring only a documentation comment. E instead changes a solver; X cites that report's correct digest, E and the scope; HEAD preserves E. Actual `admission_check` returns **no reasons**. Its only closure diff is **E→HEAD**, not R→E. The suite's positive fixture does exactly the same switch with a harmless comment (`test_c1_admission.py:114–125`), but never tests an extra or wrong edit.

Two related actual decisions also return no reasons:

- `_review_signs(report,Q)` accepts a report whose verdict explicitly reviews R, when Q appears only in “Previous review of Q was BLOCK.” The commit test is merely substring presence (`:82–86`). This can select a historical unaccepted tree as the reference or correction.
- With all report/reference/digest substrings present, X-34 text **“historical count build DENIED … do not read inputs”** passes scope binding (`:131–136`). It is not an affirmative fitting-exposure record.

For invalidation, a correctly hash-bound correction report saying **SIGN WITH EDITS**, with required changes explicitly still unimplemented, returns `[]` from `invalidation_problems`. Unlike admission, invalidation does not even require an `edits_commit`. This is a concrete release defect within the local-record convention, not a demand to make repository authorship unforgeable.

### N2 — High: the proposed parquet-independent completion witness accepts a truncated prefix

`count_meta.py:141–165` checks a completed status and `atBatIndex == enumerate(allPlays)`. Every prefix beginning at zero satisfies that rule. Neither the terminal extent of the game nor independent feed totals is checked. The box BF is recorded but ignored by verification.

**Verified:** a Final-labelled feed with exactly two plays, indices 0 and 1, matching two parquet rows, and boxscore **battersFaced=27 for both starting pitchers** is certified with no reasons. Both BF outputs equal **1**, and the contradictory 27s survive as descriptive values. Removing the box BF fields is also allowed. A final label on the game is not a completeness certificate for its `allPlays` payload, particularly when the parquet could share that truncation.

The prompt's intentional-walk objection is correct for **naive equality** with production-definition BF. It does not justify discarding the independent check. A completeness reconciliation can account for intentional walks and any other explicitly supported official-definition differences, while preserving the frozen N/BF definitions. It must reject unaccounted differences or unavailable required completion evidence. Count the game's full relevant extent, including legitimate resumed play; merely imposing a nine-inning minimum would mishandle Completed Early and is not a proposed fix.

### N3 — High: the order allowance is too loose, and the zero-PA rule is too strict

`count_verify.py:39–51` advances the slot after every nonempty result. It permits the same slot whenever the inning number differs, without proving an unfinished batting turn, an inning-ending runner out, or even forward inning chronology. It also never anchors the first actual batting turn to slot 1. `_zero_pa_problems` substitutes the **number of play-result records** for the number of batting turns reached (`:71–80`).

**Verified with independent synthetic PA counters:**

- Full nine-player sequences starting **2,3,…,9,1** for both sides are certified. This is a cyclic pattern without the first-slot certificate required by the registration.
- After all nine away slots have completed a `single` in inning 1, slot **9 repeats** in inning 2. All slots have been seen, and verification returns **[]**. The repeat allowance never examines the previous result.
- The new legitimate caught-stealing control from `test_count_build_parts.py:145–149` produces **“away: slot 3 starter 103 has no PA and no replacement evidence”** under full verification. Its away records are slot 1, slot 2's inning-ending CS, then slot 2's next-inning PA: only two turns were reached, but `len(side_pas)==3`. The test asserts only absence of a batting-order message, so it misses this quarantine.
- A synthetic nonterminal runner out followed by the same batter completing his turn **within the same inning** is rejected as a slot jump. This checks the stated logical contract; I did not inspect whether that event is represented as a separate `allPlays` entry in every historical feed version. The implementation must use its supported feed event/action/completion evidence rather than assume every result consumes a turn.

Using all plays to retain intentional-walk/order information is appropriate. Treating all results identically is not. A sound rule distinguishes completed batting turns (including intentional walks for order), open turns and supported substitution/action transitions. Zero-PA evidence must use those validated turns/slots rather than record count. These fixes reject their intended positive control while leaving other false greens; no historical incidence is inferred.
