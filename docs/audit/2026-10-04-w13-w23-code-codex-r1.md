## Findings

**F1 — P1, W2.3: conflicting identities can enter the scored pool, and “latest schema-valid” is not implemented.** Locations: `scripts/audit/mlb_benchmark/core.py:86`, `:96`, `:112`, `:38`; `scripts/audit/mlb_benchmark/run.py:80`, `:88`, `:105`, `:110`.

The round resolver collects IDs only after filtering to the requested date. A sheet containing `{id:100,date:July5}` and `{id:100,date:July6}` resolves round 100 for July 5 instead of rejecting the contradictory mapping. Unit completeness checks only the set of feed IDs, and game inference ignores raw unit IDs. Two rows with the same unit ID 99, one mapped to game 9000/squads 1–2 and the other to game 9001/squads 3–4, pass completeness against schedule `{9000,9001}`. Player 1/squad 1 then receives a supposedly unique game 9000. Both independent probes return `inferred_unique_game` and `mlb_p=0.6`, where gate 1 requires unavailable/conflicting linkage. These are contradictions in the independent universe, not a slate-only uniqueness issue.

`_load` converts a missing expected list to `[]`; it does not distinguish schema-invalid bytes from a valid empty whole sheet. In the probe, a newer `{"unexpected":[]}` MSP capture suppresses an older valid forecast. The code chooses the malformed 15:00 capture as valid empty support; the design requires selecting the latest **schema-valid** whole capture, which would be the valid 14:00 sheet. Non-list values and primitive items can instead raise. Required identity types are also unvalidated before `int(feedId)` coercion.

There is an additional internal inconsistency: `prepare_date` filters invalid probabilities before `forecasts_asof` performs its duplicate-batter exclusion. A player appearing at both 0.6 and 1.2 is reduced to a singleton and accepted; it bypasses the helper's declared duplicate exclusion. Resolve duplicate/conflicting identities on the raw sheet before score-validity filtering and count the disposition. Evidence key: `F1_w23_identity_and_schema`.

**F2 — P1 for W2.3, P2 for W1.3: failed draws still produce unqualified finite percentile endpoints.** Locations: `scripts/audit/mlb_benchmark/metrics.py:99`, `:122`; `scripts/audit/mlb_benchmark/run.py:173`; `scripts/audit/w13_tests/core.py:114`; `scripts/audit/w13_tests/run.py:198`.

The collectors compute percentiles after `v[np.isfinite(v)]`. They disclose `n_failed`, but do not make the nominal interval unavailable or mark the remaining interval conditional on success. A two-date population has identical full-rank predictor support on each date, all no-hits on date 1 and all hits on date 2. Its combined encompassing MLE is finite. Of 200 joint date draws, **111 fail** and **89 succeed**. W2.3 nevertheless publishes `delta_log_loss` interval `[0,0]` and a finite MLB-coefficient interval from those 89 successes. Its failure reasons are lost in the scalar-NaN adapter. This violates gates 5/6's unavailable-interval contract.

The same population produces W1.3 E5 intercept and slope intervals `[0,0]` with 111 `one_class` failures, without an explicit conditional-success label. W1.3's E5 calibration flag correctly becomes unavailable, and `directional_flag` correctly blocks E4/E6 labels when draws fail; those guards do not fix the interval representation. The same issue affects failed AUC/disagreement/half draws through the shared collectors. Evidence: `F2_failure_intervals`. No adaptive retries or penalized replacement were observed.

**F4 — P1, W1.3 E2: sensitivity rows dilute the primary flag; a below-threshold mismatch is labelled parity.** Location: `scripts/audit/w13_tests/run.py:105` and `:408`.
