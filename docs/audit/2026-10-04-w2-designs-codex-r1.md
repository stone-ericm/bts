## (A) findings

**A1 — Blocking: a calibration contrast cannot identify target semantics.** Design A:25–29 admits no definition but treats an interval excluding zero as resolution. T1 and T2 use different outcome populations; their signed calibration residuals can differ solely because no-PA rows change the denominator. A significant difference does not establish that either target fits, identify what MLB intended, or distinguish conditioning on starting, a PA, or an AB. Synthetic probe: ten identical dates, each with eight hits and two no-PA rows, every forecast 0.1. Mean stated-minus-realized residuals are −0.7 for T1 and −0.9 for T2; the date-bootstrap contrast interval is [0.2, 0.2]. The proposed ambiguity condition is false although both targets are badly miscalibrated. Using absolute residuals would still not identify semantics. Smallest fix: always label this read association/target sensitivity unless independent documentation or archival evidence defines the target. The bridge's evaluation population also does not prove that served p is literally P(hit | PA). W4 rank 1 retains its independent target/availability kill condition (plan:188).

**A2 — Blocking: `unit → game_pk` does not connect these forecast rows to a unit.** A:13 lists only roundId/playerId/probabilityStarter/numberSelections; A:23 nevertheless promises doubleheader resolution through a unit. The capture test uses that four-field shape (`tests/leaderboard/test_static_capture.py:21`). `parse_players` provides playerId→feedId/squadId; `parse_units` provides unitId→feedId/roundId, but neither supplies the missing forecast→unit edge (`sources/static.py:57,75`). The ledger's `match_slot` works because a contest slot already has unitId (`season_ledger/contest.py:106`). Its match cannot simply be reused for a forecast lacking one. Synthetic inputs with one batter and two same-round units produce games 9001/9002 and no distinguishing forecast field. Normalized unit rows also discard team/lineup fields (`sources/static.py:35,87`); those remain only in raw captures. Smallest fix: freeze the exact raw-field linkage before outcomes, preserve IDs/locators, exclude unresolved or multiply linked forecasts, and distinguish a complete unique-game inference from a witnessed unit link. Do not let the shared slate itself hide a second game, or copy a forecast to both games.

**A3 — Material: “as of written_at” and “age is an upper bound” overstate the archive.** A:21,30,58. `capture_all` samples `now` once before all sequential fetches; `capture_one` uses it in the filename after fetching (`static_capture.py:105–138,142–154`). It is a run-start stamp, not a response-received timestamp. A run stamped 12:00 can fetch a changed sheet after a 12:00:30 slate write while appearing to precede it. This is a possible timing failure established by control flow, not a claim it happened. Each feed is deduped independently, so required lookup files need not share the forecast's stamp. The slate writer overwrites one daily file and stamps the write, not the lock (`src/bts/slate.py:10,61`); the bridge already states this limit. Further, age since a stored sheet observation is not an upper bound on model-generation age: a newly stored sheet can change only numberSelections while an individual probability remains old. Without fetch history, missing snapshots do not prove continuous successful observations or unchanged content. Smallest fix: retain observation-age and timing uncertainty labels; use existing receipt/attempt witnesses when available, otherwise publish reconstructed diagnostics rather than certified cutoff availability. Reuse the bridge's separate eligibility/provenance strata without silently pooling surrogate eligibility into the primary table.

**A4 — Material: the paired estimands are not fixed by “date-weighted” or reuse of bridge helpers.** A:32–38. Bridge §6 makes AUC equal-date but proper scores/residuals row-weighted; `core.brier` and `core.log_loss` average rows (`core.py:113–120`). Synthetic two-date example: ten rows with loss 0.81 and one row with loss 0.01 yield row-weighted Brier 0.73727 versus equal-date 0.41. Specify the W2 override. Also freeze a common valid-score/identity/eligibility pool before outcomes, deterministic ties, unknown handling, and the common-known-winner dates used for paired top-1/disagreement contrasts. Synthetic unilateral unknown: independently reported top-1 rates are 0.5 versus 0; on common-known dates both are 0. Never select again after T2 excludes a no-PA winner. The existing bootstrap preserves repeated draws, but an equal-date statistic that regroups by original date would collapse their multiplicities. Define weights on bootstrap draw blocks and retain the bridge's exchangeable-date/support limitations.

**A5 — Material specification gap: the encompassing comparison lacks its reference fit and failure rule.** A:39. An in-sample log-loss change needs an ours-only logistic model with the same intercept, slope convention, weights and rows; comparing the full fit against raw served p would confound recalibration with MLB information. Unbounded logits, exact collinearity and separation can make coefficients/intervals undefined. Freeze clipping, fit convention and the rule for failed bootstrap refits before results. The smallest descriptive check uses an intercept in both fits, no interaction/search, and reports unavailable coefficients/intervals when MLE is not identifiable; it does not adapt penalties after seeing failures. The nested in-sample gain is a fit diagnostic, not out-of-sample benefit or a promotion gate.

**A6 — Exposure gate is correctly ordered in intent, but needs full scope.** A:44–48 discloses X-21. X-23 must cover the actual joined population, both targets, winner outcomes, residual-model fitting/refitting and inspection of prepared outcome tables. It must disclose already-consumed production-selected outcomes (X-01/X-09) and the research-only stratum (X-12), as applicable. Register:35 currently permits the unread late windows only for old protocols or W1.2; the published X-23 must explicitly record the bounded W2.3 descriptive permission so that this old sentence does not contradict the new row. No 2026 candidate test is admitted. The design's popularity restriction, no popularity weighting, and prospective-only combination boundary can remain.

**A7 — Material, confirmed in code added during review: absent rows are carried forward despite a newer changed sheet.** The new `forecasts_asof` accumulates each player's last listing across all older snapshots (`scripts/audit/mlb_benchmark/core.py:7–23`); its test expressly requires a player absent from the latest sheet to survive (`tests/scripts/test_mlb_benchmark.py:29–32`). This is not content-dedup carry-forward: a changed, stored latest sheet is a full new observation of the popularity-selected support. Synthetic 17:00 sheet lists 701/702; 20:00 lists only 701; cutoff 21:00 returns both. A:21 says use the last capture, not the union of all previously listed players. The implemented rule changes coverage and the candidate population. The new `join_to_slate` also checks doubleheaders only by duplicated batter rows in our slate (`core.py:26–39`), so a two-game batter with only one slate row is matched as unique. Synthetic single-row slate returns matched_unique=1 and ambiguous_doubleheader=0 without any independent game universe. The smallest fixes are whole-sheet latest-capture support and independent game linkage as specified in A-E2. The three new tests do not establish either boundary.
