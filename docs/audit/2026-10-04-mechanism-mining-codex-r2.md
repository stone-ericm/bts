## Findings

1. **P1 — A result conflict changes the consensus winner before settlement.** `scripts/audit/mining87/consensus.py:26` includes `result` in `OBS_IDENTITY`; `:90–94` discards a user's vote when the latest-stamp result observations disagree, even if the batter and unit agree. This violates R1's requirement that outcomes or missing outcome support must not cause a new modal winner to be selected. Synthetic inputs: users `a,b` choose batter 20 and user `c` chooses batter 10. The frozen winner is 20 with two votes. Adding only another latest-stamp observation for `a`, same batter 20 and unit 500 but `not_hit` instead of `hit`, removes `a`; the remaining 1–1 tie selects batter 10. This changes the selected batter, share bin, tie sensitivity and potentially every paired result. The missing record cannot simply be called an ambiguous *vote*: the vote identity is known and the ambiguity concerns settlement. **Fix:** retain that user's one identity vote, carry settlement ambiguity separately, and leave the selected batter's outcome unresolved rather than choosing a replacement. **As-is limit:** consensus is conditioned on result consistency; it is not the frozen outcome-independent consensus required by A2.

2. **P1 — A settled label without a unit can borrow another voter's pending unit.** `consensus.py:167–176` constructs the unit set and label set independently. The producer explicitly uses `unit_id=0` when absent (`src/bts/leaderboard/scraper.py:316`) and emits pending as an empty result (`:339`). The synthetic call `consensus_settlement(["hit", ""], [0, 500])` returns `("hit", "settled", 500)`: no observation actually supplies a settled hit on unit 500. This fabricated resolution enters the joint-resolution mask and can also be paired to a model probability when unit 500 is game-bound. The same problem exists for `not_hit` and `void`. **Fix:** keep result/unit observations paired and refuse transfer of an unbound settled label to a different observation's unit. Preserve the selected id and mark settlement unknown when a settled observation lacks the required unit identity. **As-is limit:** public resolution is a union of independently observed labels and units, not evidence of the selected contest target's settlement.

3. **P1 — A nullable selected game crashes the driver even with no ranked inputs.** `scripts/audit/mining87/run.py:153` calls `int(r["production_game_pk"])` for every retained primary before checking whether any slate or witness exists. `LEDGER_SCHEMA` permits null games; `scripts/audit/season_ledger/sources/pick_files.py:60` explicitly accepts an unrecorded game. The published ledger memo documents two `selection_game_pk_unrecorded` matches for the 3/29–3/30 files (`docs/audit/2026-09-28-season-ledger.md:93`). In a compiler-schema synthetic fixture, a committed primary with `game_pk=None` is correctly retained by `project_locked_slots` as an unresolved unit, but `admit_dates(locked, {}, {})` raises `TypeError: int() argument ... not 'NoneType'`. Whether those actual documented rows are retained commitments was not verified here; the schema incompatibility is verified. **Fix:** preserve nullable identity through surface preparation and refuse admission for an incomplete selection identity, while retaining the production unit. Do not drop dates to make the driver finish. **As-is limit:** the driver cannot complete the A1 inventory if any retained primary lacks game identity.

4. **P1 — COMPLETE can certify input hashes different from the bytes used.** `run.py:188` hashes inputs once, then the loaders reopen files; `load_public_picks` also enumerates the directory again (`consensus.py:37`). There is no verification or byte snapshot binding those subsequent reads to the manifest before `COMPLETE.json` is written (`run.py:297–308`). In a deterministic synthetic boundary probe, the first production loader replaces `other0.parquet` after `hash_inputs` and before the public loader. The generated vote artifact contains the newly inserted batter 987654, while `input_manifest.json` still contains the old file SHA256. The run returns 0 and writes COMPLETE. This is not a claim that the real corpus is being concurrently changed; it proves the manifest's asserted identity can be wrong. **Fix:** load the pinned bytes/inventory, rather than reopening mutable paths without validation, and refuse completion on any mismatch. **As-is limit:** hashes identify a pre-analysis observation of the files, not the inputs used to compute the report; COMPLETE attests only output-file hashes.

5. **P1 — The permitted technical retry is not bound to the same code, documents or failed-attempt pins.** `run.py:193–204` rejects changed input hashes and registration fingerprint, but a changed code-file map merely sets `retry_of.code_identical=false` and execution continues. Document hashes are not compared. `code_identity.worktree_dirty` is recorded, never refused. A synthetic mock of a changed `inference.py` hash and `worktree_dirty=true` produced another completed **registered** run with `code_identical=false`. This probe changed identity metadata in memory, not the tracked implementation; the missing rejection is the verified defect. Separately, `input_manifest.json` is first written at `run.py:291`, after all outcome-bearing computations. Injecting a technical failure at the first loader leaves an empty `.partial` directory, with no manifest to supply to `--expect-inputs`. That undermines the documented same-input/method retry rule precisely when it is needed. A fresh invocation can also omit `--expect-inputs`; the current test explicitly allows another completed registered run after a completed first run (`tests/scripts/test_mining87_run.py:307–313`). The single-completed-run rule is currently procedural, not enforced. **Fix:** persist non-outcome pins before loaders and make code/document/input agreement a rejection condition for registered attempts/retries. Reject a technical retry of a completed run in the designated registered output location. **As-is limit:** the CLI enforces selected numeric/string parameter values and the exposure gate; code/input freezing and the single-run rule require external execution control and are not established by its registration fingerprint or completion receipt.

6. **P2 — An unavailable legal DD can escape the primary-tie sensitivity flag.** `consensus.py:152–153` returns before computing primary dependence. With primary counts `{1:1, 2:1}` and DD counts `{1:1}`, the chosen primary 1 leaves DD unavailable; choosing the other tied primary 2 would make DD 1 available. The DD's availability therefore depends on the primary tie, but the adapter reports `tie_dependent_on_primary=false`. It retains that unit in the sensitivity and understates the tie diagnostic. An independent enumeration of **729** pairs of count tables over three ids with counts 0–2 found all legal id choices correct, but **22** dependency-flag mismatches, all in this unavailable-choice boundary. This does not fabricate a resolved DD or change its hit rate, but it makes the promised inventory/sensitivity wrong. **Fix:** calculate dependence before the no-legal-id return, allowing the alternative legal choice to be `None`. **As-is limit:** dependency flags cover chosen DDs only; sensitivity inventory is incomplete for tie-dependent unavailable DDs.

7. **P2 — §A5 misdescribes missing context, doubleheader bins and the reason condition 5 cannot pass.** `docs/sota_audit/2026-10-04-mechanism-mining-amendment.md:48` says all five context axes read `missing` and their cells are "empty or untestable." The missing weather value maps to **`indoor_or_missing`**, per the frozen original bin, while the other four map to `missing` (`units.py:96–101`). These are retained categories, not cell exclusions: `inference.cell_inventory` groups them and testability depends only on resolved disagreement count. A synthetic missing-context cell with 30 units was testable. Missing context removes distinctions the analysis could have made; it can pool more observations into a remaining cell. It does not automatically make that cell sparse. The doubleheader sentence at amendment `:50` also needs to distinguish rank from probability: `surfaces.consensus_surface` retains the best batter rank for multiple game rows, while only probability becomes unavailable. The existing units test itself expects `rank2` plus `missing_surface` probability for this case. Finally `:47` ties all mechanisms' lock availability to public-consensus visibility, although condition 5 concerns the mechanism's **operational** variables, as R1 stated. A production-variable mechanism could satisfy condition 5 without public consensus being available live; the current synthetic inference tests already demonstrate that. For this execution, empty frozen records are the binding condition-5 reason. All-tracked cells have nomination conditions null, so "unknown for every cell" should mean every **fixed-cohort** cell. **Fix:** use the verbatim replacements below. **As-is limit:** §A5 overstates both the code's missingness behavior and the logical reason nomination is unavailable.

## Edits

These are required corrections, not source changes made by this review. Keep the registered scientific choices fixed. No new acquisition, context pipeline or witness platform is requested.

1. **Separate latest vote identity from settlement ambiguity.** In `consensus.latest_observations`, select the latest stamp without consulting outcome labels; reject a vote only when its latest observations do not establish one valid batter id. Keep exactly one vote when that id is consistent, even when unit/result evidence conflicts. Carry all tied latest settlement evidence for that vote, or an explicit ambiguity reason that the settlement resolver cannot erase. A differing unit with the same batter must not choose another batter either. The regression case in finding 1 must keep winner 20, count 2, denominator 3 and share 2/3; the chosen id's settlement is unknown. Do not merely remove `result` from the identity and then keep an arbitrary result row.

2. **Bind settled labels to their own units.** In `consensus.consensus_settlement`, resolve paired `(unit_id, result)` observations. A recognized settled observation with a missing/nonpositive unit makes settlement unknown (`settled_observation_without_unit_identity`, or an equally explicit fixed reason); it cannot borrow another observation's unit. All valid units must still agree and settled labels on that target must agree. Preserve the existing supported case of a hit and a pending observation both on unit 500. Add hit/not-hit/void variants of finding 2, plus missing-unit pending observations, without changing identity votes.

3. **Preserve null selected game identity.** In `run.admit_dates`, replace the unconditional conversion of nullable production identity fields with `None if pd.isna(value) else int(value)`. Treat a present primary whose required identity is incomplete as an explicit non-admission; `selection_consistency` must not mistake missing identity for a match. The row must reach `units.parquet` as production-unresolved with missing surface values. Add an end-to-end fixture with a committed, null-game primary and no slates/witnesses, plus one with a candidate slate; both must complete without admitting that date or dropping the unit.

4. **Bind the computation to frozen bytes and inventory.** Use the already hashed public-file inventory rather than a new glob for analysis. Either read each input once into a byte snapshot that is both hashed and parsed, or copy/hash it into an immutable attempt input set and use only that set. Include ledger, snapshot, public picks, slates and optional files. Refuse completion if the consumed inventory/bytes differ from the frozen manifest. A final rehash alone is weaker than hashing the bytes actually consumed. The finding-4 replacement probe must either use the original pinned bytes or abort without COMPLETE; it must never report the old hash while analysing the new batter.

5. **Persist and enforce execution pins before loaders.** Write the non-outcome input manifest immediately after reserving the attempt directory and before `load_accepted_ledger`. Bind that manifest to the designated registered attempt before outcome reads; a technical retry must use it. Compare the input hashes/inventory, registration fingerprint, run mode, relevant code-file hashes and frozen document hashes and raise on any mismatch. Refuse dirty/unverifiable relevant tracked code in registered mode. Keep the planned X-22 gate activation separate from an algorithm change. A code-hash mismatch may be diagnostic metadata in exploratory mode; it cannot remain a permitted registered retry. A completed registered attempt in the designated output location is not a technical failure eligible for retry. Replace the existing test that accepts a second completed registered run with refusal; add a loader-failure test proving the partial manifest remains available and unchanged. This is a bounded execution guard, not a global platform or a claim to prevent a user invoking a different output root.
