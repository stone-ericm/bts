## Verdict

REVISE

S1's producing-model mechanism and R10's local lineup-state change are sound. S2 addresses the demonstrated changing-pick-input counterexample, but does not finish the requested sample binding. S3 does not yet specify how forecasts survive failures of the newly required buffers. The proposed gate and cost measurements cannot establish the design's full observability-only contract. Resolve these points before building; this review authorizes no deployment or operation.

## Findings

1. **HIGH — S3 specifies exception containment without specifying recovery of the original computation.** Design lines 37 and 45–48 require full-file buffers and say every added step catches `Exception`, records null/error, and leaves forecasting unchanged. After `read_bytes` or `BytesIO` allocation fails, however, the consumer has no buffer to parse. Catching the exception alone cannot supply a PA frame or cached model. In calibration, falling through to the existing outer exception handler preserves a raw forecast but changes the forecast that would have been calibrated (`src/bts/orchestrator.py:119–145`). Likewise, putting buffering in the pipeline's existing failure boundary produces `None` instead of the available baseline result.

   **Measured synthetic boundary:** with the real current pipeline's parquet loading and cache/training branch, feature computation/training/prediction leaves stubbed, the original path parser returned `[0.8]` while `Path.read_bytes` for that same synthetic parquet was forced to raise `MemoryError`. With the real calibrator and only base prediction substituted, current `predict_local` still returned `[1.0]` under the same added-buffer fault. A future implementation returning `None` or raw `[0.8]` would violate the contract. These establish the baseline and the necessary failure direction; they are not executions of nonexistent proposed code.

   Hash failures must preserve an already read buffer and its parsing/application; capture-buffer failures need a specified way to execute the original load/parse operation with incomplete provenance. Witness-list accumulation, map-state extraction, metadata transport and cached-model hashing also need containment, not only the listed post-prediction/build tests. Actual model loading, parsing, training and prediction errors must continue to have their original semantics.

2. **MEDIUM — the training serialization change can change cache behavior even when bytes match on success.** Design lines 33 and 65 compare `pickle.dumps` with `pickle.dump`. Current `save_blend` creates the parent and opens/truncates the destination **before** serialization (`src/bts/model/predict.py:143–148`); the proposed serialize-hash-write sequence serializes before opening it. A serialization exception therefore leaves different cache contents.

   **Measured synthetic counterexample:** starting both paths with a five-byte pickled empty dict, an object whose reducer raises `ValueError` left the current save's file at **0 bytes**, whereas serialize-before-open left the old **5 bytes**. This is an error-path counterexample, not evidence that a production LightGBM model has such a reducer. It demonstrates why successful-byte equality cannot prove unchanged save semantics. Full-buffer serialization also adds an allocation failure that the current streaming writer may avoid. Hash failure must not suppress the original required save or prediction.

   **Positive check:** a real tiny LightGBM blend produced byte-identical `dump`/`dumps` output at the current default protocol, and round-tripped identical probabilities. Normal serialization is plausible; the error-path contract remains unspecified.

3. **MEDIUM — S2 lacks the sample-identity and `n_fit` contract requested by r2.** Design lines 36–42 add PA/pick hashes and a map-state hash. That closes r2's demonstrated unwitnessed historical-probability input on successful capture. But r2's smallest fix also says to bind the fitted map's **sample identities**. There is no sample list or sample-binding digest here, no definition of `n_fit`, and no specified way to get that information from `fit_calibrator_from_picks`, which currently returns only a calibrator (`src/bts/model/calibrate.py:115–146`). Its private resolver returns only `(p,y)` pairs, discarding date/batter/slot identity (`49–112`).

   **Measured:** two synthetic histories with the same PA rows and changed historical probabilities mapped raw `0.8` to approximately **0.5** and **1.0** with the real fitting/application code. Their pick-byte and map-state hashes differed, as the proposed mechanism should record. Each fit used **30 samples** but had **2 isotonic thresholds**. Neither threshold count nor pick-file count defines fitting sample count, particularly with double-down and void exclusions.

   Specify ordered selected-sample identities bound to their source hashes, the actual sample count, and exact map-state canonicalization. Preserve the existing read/filter order: the resolver reads `2*.json` before checking payload date/result. Filename filtering, silently dropping a sample when witness append fails, or treating a hash failure as genuine calibrator unavailability would change behavior. `_read_text_bytes` itself is appropriate: its output matched current `read_text` on a synthetic Unicode/CRLF pick file. Retain r2's disclosed limitation: this witness does not retain every live schedule/lineup response and is not complete replay evidence for every prediction input. That is not a request to bring step 2b into this review.

4. **HIGH — the golden and transport gates are useful but insufficient for the stated behavior contract.** Design lines 55–72 compare selected frame values, pick/decision bytes, and a scheduler-produced slate for cache/train/calibration/error paths. Stubbing **only training leaves**, while keeping actual pipeline branching, loading, serialization and calibration, is a valid deterministic test of those fixtures. It is not proof for omitted scheduler paths, cache/error side effects, or timing-dependent delivery. A changed lock/defer/delivery decision can leave pick and slate bytes unchanged. A golden generator also needs fixed clocks to compare timestamp-bearing pick and decision bytes exactly.

   The current transport is straightforward: scheduler normal and fallback refresh call `run_and_pick`, whose real cascade returns the frame and which calls `save_slate` before selection (`src/bts/scheduler.py:1629,2038`; `src/bts/orchestrator.py:222–240,270–280`). There is no intervening concat/copy in this path. The proposed scheduler-chain test can certify that transport **if** it keeps `predict_local`, `run_cascade`, `run_and_pick` and `save_slate` real and patches lower computation/I/O leaves. Patching `run_and_pick` or supplying an already witnessed frame at the scheduler boundary would bypass the transport under review.

   Missing red/green cases include capture-buffer allocation failures, successful forecast plus cache-hash/map-metadata failure, original load/parse/save errors, unavailable calibration, skip/private, fallback with a cached pick, and restart. Require delivery/transport traces and selected identities/action/partners, eligibility/lock/defer results, cutoff-minus-epsilon and exact-cutoff behavior. Add a mutant that changes a downstream lock/defer/delivery result while leaving slate/pick bytes unchanged, plus a mutant that drops attrs between the local tier and persistence. The current ledger's witness-only mutants cannot prove those gates.

5. **MEDIUM — the cost plan measures useful quantities but has no production-safety acceptance rule.** Design lines 75–79 count input hashes and ask for Mac wall time/peak RSS. The inherited witness also scans/hashes recipe sources, inspects serving functions, queries package versions, holds cached-model bytes, and adds attrs/envelope serialization. Training now holds a serialized blend buffer; calibration traverses all matching pick files before date filtering. Those costs are not captured by the phrase “one extra hash per input buffer.” Swallowing exceptions imposes no latency bound, and synchronous work before selection can consume the submission window.

   Report paired baseline/candidate runs in fresh processes with identical synthetic inputs, realistic compressed **and decoded** parquet sizes, and distinct cold training, warm cache, calibration-off/on and unavailable-calibration cases. State whether training is real or stubbed, isolate measurement phases, include the persistence/selection path, and report buffer lifetimes, repeats and variability. Fix acceptance criteria for incremental latency and peak memory before evaluating the measurements, with a declared relation to production memory/deadline headroom and a stop/revision consequence. Mac measurements cannot establish installed-box behavior; do not turn them into a claim of deadline invariance. No production cost was measured in this review.

## Required changes

1. **Amend §3 S3 with an executable recovery rule.** On successful buffered reads, hash and parse the same bytes. On an ancillary capture-buffer allocation failure, run the original load/parse path, mark the corresponding provenance incomplete, and preserve its original error semantics. On hash/metadata failures, continue consuming the already available input and applying the real calibrator. Do not retrain because a cache hash failed; do not substitute raw probabilities because calibration provenance failed. `applied` must describe the actual returned forecast even when its provenance is incomplete. Define error collection and attrs attachment so their own failures cannot replace an available forecast. Add independently injected failures at these boundaries and assert equality with the baseline forecast, calibration result and selected behavior.

2. **Amend §3 S1 with the save-operation contract.** Keep the existing cache/training truthiness, required save-path choice and cached object's `_model` handling. Returning provenance from that actual branch closes the empty-cache mismatch; retain the loaded-buffer binding and avoid later pathname rereads. Specify how exact serialized-byte hashing preserves write/serialization failure behavior and avoids a new mandatory full-buffer allocation. One implementable approach is to keep the original serializer/writer and hash the exact bytes it forwards, with hash failures disabling only provenance. If using a different approach, spell out its fallback and open/truncate ordering. Add original save-error/cache-content checks, hash-failure continuation, and real model serialization/round-trip validation alongside the existing empty-cache and path-replacement cases.

3. **Complete §3 S2's producer contract.** Define `n_fit` as the number of selected `(p,y)` fitting samples. Record ordered sample bindings including source file/hash, payload date, batter identity and primary/double-down slot, with values/outcomes either included or bound by a specified canonical digest. Define exact map-state keys, ordering, encoding and finite-number serialization. Specify the optional metadata API without changing the existing calibrator return contract or selection/filter/fallback rules. Add double-down, void, malformed/skipped-pick, insufficient-support and sample-metadata-failure fixtures. Step 3 must refuse required incomplete bindings while permitting genuine registered unavailable-calibrator fallback.

4. **Expand §5 to cover the full contract in finding 4.** Pin the baseline commit, generator bytes/command, fixture hashes, numeric environment and fixed clocks. Compare ordered row identities and all forecast values used by selection, cache bytes and error side effects, selection/lock/defer/action/partners, delivery/transport traces and cutoff behavior. Keep real transport functions in the attrs test and kill both the attrs-loss and unchanged-output decision mutants. Describe golden equality as evidence for the tested deterministic scenarios, with real-model and fault/deadline checks providing separate coverage.

5. **Expand §6's cost and certification acceptance language.** Include the complete synchronous witness cost and the predetermined cost acceptance criteria described above. Keep final-diff/call-graph identification of affected W1.5 current-defence certificates, use frozen tooling `f453283`, run at the final candidate, and require both runner `accepted` and recorded reviewer `accept` with retained evidence. Do not assume the seven 10/06 certificates are automatically the complete set or that missing-delivery absence can be certified by Phase 1. Certification does not replace the behavior and cost gates or Eric's D7.
