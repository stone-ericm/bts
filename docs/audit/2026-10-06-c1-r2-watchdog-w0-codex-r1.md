# W0 production-code review, round 1

## Verdict

**BLOCK.** Reviewed `a1607c88c5d90a80c401362512a87e0b8886b344`, initially clean and detached. The foundation does not yet satisfy R5 or gate 2: actual owned-root operations can mutate outside the root, and the purported syscall tracer gives false greens for several such mutations. Notification recovery/recurrence and lease ownership also need correction before checks depend on this skeleton.

The authorized baseline command, `UV_CACHE_DIR=/tmp/uv-cache uv run pytest tests/watchdog -p no:cacheprovider`, passed **16/16**. Independent synthetic probes reproduced the failures below. No tracked source or tests were edited. No real data, configuration, environment/credential files, contest requests, DNS/network calls, SSH, or real DM transport were used. CLI probes patched `bts.dm.send_dm`; all sends described below are local fake calls.

**Review-process deviation:** the first tool call read the prompt in parallel with a search of the memory registry, before discovering the prompt's checkout-only restriction. That external search should not have occurred. Its results were excluded from the review; every substantive finding below comes from this checkout and synthetic probes. There were no subsequent external context reads.

## Confinement

**B1 — validation is separated from mutation.** `root.py:43–59` returns an ordinary pathname; `ensure_dir`, `write_atomic`, and both lock implementations subsequently resolve it again through the filesystem. Neither another `child()` check nor a check after mutation closes that race.

Measured, with real filesystem operations on synthetic directories and an interposition solely to schedule the swap after validation:

| Operation | Probe placement | Actual result |
|---|---|---|
| Atomic write (`root.py:88–94`) | Immediately before opening the validated temp path, move `results` aside inside the root and replace it with a symlink to a synthetic sibling directory | `write_atomic` succeeds; `escaped.json` containing `escaped` is created in the sibling, outside the root. The temp write, replacement and directory fsync all use the redirected directory. |
| `ensure_dir` (`root.py:62–64`) | Replace `branch` with an outside symlink immediately before `mkdir` | The outside `created` directory is created; only the subsequent re-check raises `RootError`. Refusal occurs after the forbidden mutation. |
| Job lock (`root.py:71–74`) | Install an outside-target symlink at the lock filename immediately before `open(..., "a")` | An outside file is created and its descriptor is flocked. |
| Notification lock (`notify.py:42–43`) | The same swap at `.lock` | An outside file is created and flocked. |
| Cached root replaced after construction | Rename `watchdog` aside, replace it with an outside symlink, call `ensure_dir("new", "nested")` | Outside directories are created before `RootError`. `child()` does not inspect `self.path` itself, and its nonexistent-parent branch does not resolve the path (`root.py:51–56`). |

These are deterministic reproductions of possible interleavings, not claims that such a swap occurred in production. Static absolute/`..` and already-present descendant symlink refusals work in the supplied cases. They do not establish race confinement.

**Atomicity is also overstated for concurrent callers.** The temp filename is only target name plus PID (`root.py:88`). Two threads writing the same target share it. I paused the first after opening that temp and before writing, let the second write and publish `BBBB`, then resumed the first. The published target changed to `AAAA`, and the first call raised `FileNotFoundError` at replacement. Thus one caller can mutate another caller's already-published inode. Current notification calls are normally serialized by the state lock, so this probe establishes a defect in the generic `write_atomic` guarantee rather than an observed collision in that notification path. Use unique, exclusively created temps. The ordinary no-race flush → file fsync → replace → directory fsync sequence is appropriate; reopening the directory by pathname is not a race-safe durability guarantee, and failed calls currently leave temps behind.

**B2 — the audit hook is not a syscall tracer and is not a sound gate-2 instrument.** `tests/watchdog/conftest.py:22–35` records selected CPython audit events, not all kernel writes. A positive ordinary `os.open(..., O_WRONLY | O_TRUNC)` control produced one outside hit: its flag mask does cover the ordinary write/create/truncate/append cases. `Path.write_text`, ordinary mkdir/rename/unlink and the listed `shutil` operations produce useful events when executed in the active context. The following independent controls nevertheless mutated a synthetic outside file and returned **zero** outside hits:

| Counterexample | Trace result | Cause |
|---|---|---|
| `Path.write_text` through a final-component symlink under the root | One `open` event, classified inside | `outside()` resolves only the parent, retaining the leaf name (`conftest.py:59`). It does not follow the symlink actually followed by the write open. |
| `threading.Thread(... outside_file.write_text(...))` started inside `tracing()` | Empty sink | The new thread does not inherit this active `ContextVar` on the reviewed Python 3.12 runtime. |
| A local Python subprocess writes the outside file | Empty sink | The hook ignores process-spawn events and is absent in the child. |
| `os.ftruncate(fd, 0)` and `os.write(fd, ...)` on an outside descriptor opened before tracing | Empty sink | No open occurs during tracing; the descriptor argument is not a pathname recorded by this hook. |
| CWD under the root; `os.open("relative-file", O_WRONLY | O_CREAT, dir_fd=outside_fd)` | `open("relative-file")`, classified inside | The trace omits the descriptor base; `outside()` substitutes CWD. |

Resolution is performed after the operation, so restoring a swapped path before `outside()` runs can also conceal the target used at mutation time. That last consequence is inferred from the implementation; the five cases in the table were executed. High-level `shutil` events do not repair these gaps or cover arbitrary child/native writers. Remote-upload confinement is not instrumented either; W0 introduces no such operation, so no upload was attempted in this review.

## Notifications

**Verified in the supported sequential paths:** the state persists to disk and a new `Notifier` reads it; the same incident/date/selection/status is suppressed after a nonempty string ID. A raised fake send and an empty-ID return remain pending and later retry successfully. Syntax-invalid JSON and a non-object JSON value raise `NotifyStateError` without resetting the file. `alert_text` and the state retain incident identity; selection is stored in the dedup state, although the alert text does not itself include it.

The real implementation sends outside the **notification state lock** (`notify.py:110–118`). A fake transport independently acquired that same lock nonblocking and observed it free. The runner's **job singleton lock** remains held during enqueue/flush/network work (`runner.py:34–57`). That is different from holding the shared notification lock: another job can take its own singleton, but the same job cannot rerun until this send work ends. W0 supplies no whole-job or whole-flush deadline. The two-minute short-job requirement remains to be implemented before the complete watchdog is accepted; no bounded completion claim is established here.

**B3 — status is not escalation/recovery state.** `notify.py:88` hashes `r.status.value`, and `result.py:17` permits only fault/checker-failure results into the queue. There is no recovery event or incident episode in `CheckResult`. Executing fault → verified recovery → same-date, same-selection fault produced **one** fake send and **one** permanent state entry. The recovery is filtered out; the recurrent fault matches the original sent key and is suppressed. Changed severity/detail with the same status is also suppressed by construction. The test that hashes the literal `"recovered"` proves only that the standalone hash function distinguishes that string; the actual enqueue path cannot supply it. This fails R5's state binding and §4.3's recovery/recurrence requirement.

**B4 — leases have no completion ownership and use wall-time string ordering.**

- An older sender was paused after claiming. A second sender at +11 minutes reclaimed the entry and recorded ID `confirmed-second` as sent. The first then returned a failure. Its unconditional update (`notify.py:123–134`) changed that confirmed entry to **pending**, while leaving `message_id="confirmed-second"`. A third flush sent again. `lease_owner=os.getpid()` is neither checked at completion nor unique per attempt; threads and repeated claims in one process also share it. This is lost local confirmation, not merely the documented uncertainty after a remote-acceptance crash.
- At the fall-back boundary, a valid lease expiring `2026-11-01T01:05:00-05:00` was reclaimed at `2026-11-01T01:55:00-04:00`, **600 real seconds before expiry**. ISO lexical ordering (`notify.py:104`) orders the wall labels incorrectly across offsets.
- A claim at `01:55-04:00` computes its ten-minute lease as `02:05-05:00` (`notify.py:106`), **70 elapsed minutes** later. At `01:15-05:00`, twenty real minutes after the claim, the probe still skipped it. Both timezone-aware arithmetic and ordering need normalization to UTC before operating on elapsed lease time.
- An injected one-hour backward wall-clock adjustment retained the entry as sending. That behavior follows the current clock, so it is not by itself evidence of an expired lease being ignored; it does establish that wall-clock rollback can postpone retry and no skew policy is implemented. `now` is also captured before acquiring the lock and before a whole batch of sends. Do not describe this as a bounded retry protocol without a defined clock/send-duration policy.

Crash-before-send and crash-after-remote-acceptance need deterministic fixtures using persisted claim state. The existing expired-lease test plants only a favorable same-offset string and does not test ownership, accepted-but-unrecorded sends or clock discontinuities. Duplicate retry after uncertain acceptance remains an acceptable documented limit; confirmed state must not be regressed by a stale claimant.

**B5 — syntactically valid corrupt state can silently disappear from processing.** `load_state` validates only the top-level dict (`notify.py:59–61`). Both `{"bad":{}}` and `{"bad":{"status":"unknown"}}` passed load/flush without an error or a send. Invalid entries can therefore be silently skipped rather than diagnosed. Other shapes raise incidental exceptions. Validate entries, allowed states and required fields before queue mutation or claims; preserve the original corrupt bytes and raise a defined error.

## Statuses and failure

Normal raising and empty-return checks receive a dated `checker_failure`, and the next ordinary checks run. The fixed/system clocks produce timezone-aware ET values in their intended use. The result directory is based on the job's start ET date; result fields may legitimately refer to earlier affected dates, which should still be validated.

**A check can return a generator that yields a result and subsequently raises.** The generator probe yielded a selection-bound fault and then raised. `list(check(ctx) or [])` discarded that partial output; the saved results were `partial: checker_failure` followed by `W-ok: verified`. Thus the exception did not suppress the following check, but the emitted fault/selection was lost. Specify and test whether check results are transactional sequences or a stream. Do not imply that partial yielded results survive this implementation.

**B6 — the per-check exception boundary is incomplete, and output failures abort reporting.**

- Name lookup, including eager evaluation of `repr(check)`, is outside the try (`runner.py:39`). A callable with a raising `__repr__` prevented the following check from running. Formatting a caught exception invokes `str(exc)` (`runner.py:44`); an exception with a raising `__str__` likewise prevented the next check from running. These are concrete violations of the unqualified isolation claim.
- Returned items, status/date and JSON serialization are not validated within that check's boundary. A `CheckResult` with non-serializable evidence caused `TypeError` after later checks had run, with **no result file and no notification attempt**. An ordinary `CheckResult` with `et_date="not-a-date"` was accepted as verified and saved. Type annotations do not enforce the dated-status contract.
- A corrupt notification file caused `NotifyStateError` after both checks' results were durably saved. The result file still contained fault and verified statuses, but `run_job` returned no outcome, the CLI prints no normal counts, and the queued alert is unavailable.
- An injected results-write failure caused `OSError` after checks ran; notification enqueue/flush was never attempted and no outcome was returned. On a full filesystem there may be no possible durable report, but the CLI can still emit the collected statuses and an explicit infrastructure failure through stderr. It must not report successful completion. Output and notification failures need distinct surfaced outcomes, and failure of one channel should not automatically prevent an independent usable channel from being attempted.

**B7 — `--no-send` does not queue.** The CLI documents that alerts stay pending (`cli.py:5–6,31`), but creates no notifier at all in this mode (`cli.py:39–42`). A synthetic registered fault job exited **0**, wrote its fault result, and created **no notification state**. A subsequent normal flush cannot recover an alert that was never enqueued. Separate queue persistence from permission to send; support an as-yet-unset recipient without discarding the queued incident.

**R6:** the watchdog package itself has no authenticated contest/cookie import; its sole external BTS transport import is the lazy `bts.dm.send_dm`. The DM implementation performs allowed Bluesky auth/chat work, not contest operations. The stronger claim that the complete `bts watchdog` CLI imports no cookie/auth path is **false**: `src/bts/cli.py:59` imports the existing leaderboard CLI, which imports `bts.leaderboard.auth` and its cookie/auth functions (`leaderboard/cli.py:16–19`). Those functions are not invoked by the reviewed watchdog command, and the inspected auth module has no import-time credential read. Importing existing function definitions is not itself an R6 request or cookie-access violation. Scope the import claim accurately; no global CLI refactor is needed merely to prohibit calls which this path does not make.

## Tests

The 16 supplied tests were run unchanged and passed. The independent probes used the synced venv's `python -B`, synthetic `TemporaryDirectory` inputs and fresh `PYTHONPYCACHEPREFIX` names. Probe scripts were task-owned temporary files; source substitution occurred only in memory for the additional mutant. Deterministic event barriers were used for stale-claim and atomic-temp interleavings, and their workers terminated without unhandled errors.

**The supplied concurrency test has a demonstrated false green** (`test_w0_skeleton.py:145–167`). I moved the send loop inside the existing state-lock block in an in-memory copy of `notify.py`, then invoked the exact unchanged test. **It passed.** The main thread's second flush blocks on the lock; the worker's `release.wait(5)` times out, finishes the send and unlocks; the second flush sees sent state and returns. The test then releases an already-finished worker and all assertions pass. It proves neither a short lock nor nonblocking access during slow transport. Timed waits/joins also lack assertions that the intended release caused progress and that the worker has exited.

Other false-green limits:

- The confinement test exercises ordinary same-thread, same-process paths after root creation; its red control covers pathname writes/renames only. The independent controls above show why passing it cannot establish §4.2.
- Dedup persistence is tested through a new object, not a killed/restarted process. The on-disk mechanism is present; real process interruption boundaries remain untested.
- The literal-key state test does not exercise recovery/recurrence through enqueue.
- Corrupt-state, partial iteration, invalid output, failure-channel, `--no-send` fault queuing, DST/skew and expired-owner interleavings are absent from the suite.
- The prompt/commit report **11/11 killed** and **3788 fast-suite passes**. Those supplied claims were not independently rerun: the prompt authorizes the watchdog suite and synthetic probes. One additional, relevant lock-held-send mutant demonstrably survived the existing concurrency test. Neither supplied aggregate clears these boundary counterexamples.

## Required changes

These are the smallest fixes to W0's foundation; they do not require implementing W1 or later business predicates. No production repair, deploy, installation or activation is authorized by this review.

1. **B1: replace pathname validation as the write authority.** Anchor the admitted real root with a directory descriptor; walk/create components using descriptor-relative operations and no-follow directory opens, and open lock/files with no-follow checks. Perform temp creation, replacement and directory fsync through the admitted parent descriptor. Give temps unique names and exclusive creation; clean up only the caller's owned temp on failure. Specify/enforce directory ownership so opened directories cannot be relocated outside the owned namespace by cooperating watchdog operations. A post-write recheck is insufficient. Add the directory, root, leaf-lock and temp-swap controls above plus the same-PID atomic-write collision; outside siblings must remain untouched, and losing/refusing a race must occur before a forbidden mutation.
2. **B2: replace the unsupported gate claim with an enforceable instrument.** CPython audit events may remain supporting diagnostics. Gate 2 must resolve the actual operation target at operation time, including leaf symlinks, descriptor bases and FD-only writes, and cover or explicitly reject child/thread/native writer paths. Use independent OS-level enforcement/tracing for paths the Python harness cannot observe; do not silently accept unobserved actors. Add all five red controls above and preserve the same-byte/write-undo controls. Full-gate remote-operation coverage remains required when those later operations are introduced.
3. **B3: represent notification lifecycle independently of evidence status.** Persist escalation/recovery and a recurrence/episode identity for the incident/date/selection. Notify a genuine transition to recovery and a new fault after recovery while suppressing repeat polling of the same episode. Prove fault → recovery → recurrence for the same ET date/selection through the real enqueue/flush path, including restart; retain distinct-incident and changed-selection controls. Do not use a scalar hash-function test as lifecycle evidence.
4. **B4: fence lease completions and use elapsed UTC lease time.** Generate a unique token per claim; complete it only if the persisted active claim still has that token, so old success/failure cannot rewrite a newer confirmed state. Read a fresh aware time at admission, convert to UTC before adding elapsed duration and before comparing parsed deadlines, and define a rollback/skew policy. Do not use PID as the fencing token. Add both fall-back probes, stale-failure-after-confirmation, two claimants in one process, accepted-send-before-crash and pre-send-crash controls. Define bounded sends/batch processing before claiming bounded leases/completion.
5. **B5: validate notification entries before changing/sending state.** Unknown/missing status, malformed entries and invalid claim metadata must raise `NotifyStateError`, with the original state preserved; add syntax-invalid, non-object and valid-JSON-invalid-entry controls.
6. **B6: complete check isolation and report output failures.** Use safe check naming and exception formatting inside the isolation boundary; validate each check's typed, dated, serializable output there so one malformed check becomes checker failure without losing other checks' reports. Define the partial-generator contract and test it. Return/surface collected statuses plus explicit persistence/notification errors; make the CLI print a failure report and exit nonzero for infrastructure failure, without preventing an independent notification/report attempt when it is usable. Never mark W-self completion on failed required work. Add the naming, exception-format, malformed-output, invalid-date, corrupt-notifier and results-write-failure probes.
7. **B7: queue in `--no-send` mode.** Always persist notification candidates; skip only transport execution. A missing recipient remains a pending delivery prerequisite, and a later configured flush must be able to send that same incident. Prove a fault run in `--no-send`, then restart/configure a fake recipient/transport and confirm the queued send once.
8. **Repair the concurrency acceptance test.** Have the first sender remain blocked until an explicit release. Start the contender separately and require its state-lock operation/flush to complete while the sender is still blocked; only then release the first sender, with cleanup in `finally`. Propagate worker exceptions and assert worker termination. The send-under-state-lock mutant must fail without relying on the sender's timeout to make progress.

Round 2 should check these bounded changes and their red controls against a newly pinned diff; defer new watchdog predicates. A corrected W0 signature would still be distinct from the complete-watchdog deploy gate, D7, commissioning and A8.
