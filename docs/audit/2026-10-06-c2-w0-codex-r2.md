**E1 — the new unsent-metadata validation does not enforce the complete documented invariant.** At `notify.py:165–166`, the sent/message-ID equivalence tests whether an ID is a nonempty string. For an unsent notice, that admits `""`, `false`, a number, an object and other values that fail that string predicate. The new branch at `:172–173` rejects only a recipient. The updated design explicitly requires an unsent notice to have no recipient and no message ID (`2026-10-06-c2-w0-repair-design.md:40`), matching round 1's required change B2.

I found no new valid-state counterexample that bypasses those mechanisms in the changed code. Possible duplicate acceptance after a crash or lease expiry remains the documented transport limitation.
