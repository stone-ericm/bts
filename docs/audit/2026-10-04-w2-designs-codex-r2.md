**A-R2-1 — Latest whole-sheet support is only partly fixed.** `scripts/audit/mlb_benchmark/core.py:8–21` picks the latest sheet **with nonempty rows for the requested date**, because `dated` is required at line 19. Consequently a newer stored sheet that removes every row of that round, or is validly empty, is ignored. Synthetic case: 17:00 sheet contains round 10/player 1/p=0.7; 20:00 sheet contains only tomorrow's round 11; cutoff 21:00. The helper returns the 17:00 forecast for round 10. It also does so when the 20:00 sheet is empty. This is the same stale-support boundary as A7, at whole-round rather than individual-player level. The new tests prove removal of one player **while the requested round remains present**, not removal of the whole round (`tests/scripts/test_mlb_benchmark.py:28–30`).

Smallest fix: select the latest schema-valid whole sheet before filtering its rows to the requested round. No rows after filtering means no support; do not search backward again. A runner that supplies only that already-selected whole sheet to the helper is an equally small guard. If the helper is left unchanged, exclude and count every observation whose latest whole sheet lacks the target round; those dates cannot inherit old forecasts. A-E1 removes the ambiguity in “qualifying” in design A:21. Merely stating that old forecasts may be stale would not repair an incorrectly enlarged shared population.

**A-R2-2 — Independent game linkage now has the intended source and label, conditional on caller inputs.** `games_by_batter` uses MLB player squad and unit home/away squad/feedId; `join_to_slate` requires a singleton game set matching the slate game and emits `inferred_unique_game` (`core.py:40–73`). It no longer decides uniqueness from the slate. The existing synthetic tests cover a two-game squad even when the slate contains only one leg, absent squad, game mismatch, no game and MLB-only coverage. This resolves the earlier slate-only doubleheader defect on valid complete inputs. It establishes an inference, not a witnessed forecast→unit link.

The remaining boundaries are at input preparation, which is not yet implemented:

- **Round restriction:** `games_by_batter` does not inspect unit roundId. A synthetic forecast for round 10 and a supplied unit solely in round 11 produces a singleton game set. The caller must supply only the forecast's independently resolved round, with other-round/missing-round records handled explicitly, never inferred from our slate.
- **Completeness/invalid units:** the helper skips a unit with null feedId (`core.py:48–49`). Synthetic two-unit input for the same squad, one game 100 and one null feedId, produces `{100}` and the join labels it `inferred_unique_game`. An unresolved possible second game must make multiplicity unknown; it cannot be discarded to obtain a singleton. The capture module describes units as current/upcoming (`src/bts/leaderboard/static_capture.py:11–14`), so a filtered or rolling sheet is not automatically a complete date-game universe. No real coverage assertion was tested here.
- **Historical lookup boundary:** the helpers receive untimed dictionaries/lists, so they cannot enforce it. A synthetic change of player squad from 11 to 12 switches the inferred game from 100 to 200. The runner must freeze one historical rule before outcomes. A-E2 chooses the selected forecast sheet's observation stamp for identity/game linkage, independently selecting each lookup feed's latest whole sheet at or before that stamp; eligibility remains evaluated at slate written_at under the frozen bridge. Shared run-start stamps still leave receipt uncertainty, already stated in the design.

The normalized ledger unit parser retains feedId/roundId/status but not the home/away squad fields needed by the new helper (`scripts/audit/season_ledger/sources/static.py:35–36,75–90`). The revised design already permits reading those fields from raw static captures; this requires no change to the frozen ledger tooling. The runner must also enforce the existing conflicting-ID, probability-validity, provenance and coverage rules before these helper outputs become metric inputs. The four current tests establish neither those validations nor lookup-time selection/completeness. Missing evidence remains an exclusion or unavailable diagnostic, not a reason for additional collection.
