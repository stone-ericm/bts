## Findings

**F1 — High: `freeze.json` freezes neither source contents nor the full executing recipe; the exposure commit check is not bound to publication.** `scripts/audit/field_products/run.py:73–85,150–174,180–217,283–290`.

The pre-read freeze contains E, derived labels, filename binding/listing and hashes of only this package's eight Python files. It contains no predeclared hashes for the board/status/raw pages, identity and profile files, daily parquet contents or ledger inputs. Those enter the manifest during or after analysis. Important executed dependencies (`final_leaderboard_grab`, leaderboard parser/storage/models and `mlb_benchmark.metrics`) are outside `code_files`; an uncommitted dependency change is not detected by the recorded HEAD. Final-grab identity/path resolution also occurs after the first board outcome read. Writing a marker first is weaker than the design's source/membership/code freeze.

Synthetic probe: use `test_field_products_run._inputs`, patch only the exposure gate for this synthetic run, and wrap `C.load_board_receipts`, the first outcome step. Its wrapper reads the already-written freeze and changes every synthetic `alpha.parquet` result to `not_hit` before delegating. The run returns 0, E's pooled ratio changes from the fixture's **0.8 to 0.2**, and neither freeze nor execution reports a source change. The final manifest merely hashes the replacement. The observed freeze keys contain no source-content manifest.

A separate gate probe sets both commit constants to actual HEAD and points `REGISTER` to an untracked synthetic file containing `| X-24 | uncommitted placeholder |` and the equivalent X-25 row. `gate()` succeeds even though those rows are absent from the published register at that HEAD. Ancestor existence plus a working-file substring does not establish that either named commit published the exposure row.

**F2 — High: a May 1 username witness does not uniquely identify every later daily batch.** `cohort.py:112–142`; `run.py:162–165,191–211`.

Binding uses only the May 1 E names and directory stems, then injects the E ID into every row of a matching file. It checks collisions only among E and separately visible filename aliases. A non-E account sharing the exact username, or sharing its post-sanitization filename without leaving a distinct old raw-name file, is invisible to these checks. The scraper actually chooses one account per username with `tracked.setdefault` (`src/bts/leaderboard/scraper.py:578,605–607,622–625,651–660`). Disjoint histories need never change an already-settled slot, so the ownership heuristic cannot rescue the assignment. The design requires existing capture-time evidence binding the observation/batch, not a stable-name assumption disclosed after assigning it.

Synthetic probe: E contains only `(7, "alice")`; stems contain `alice`; the file contains a May 1 hit and a May 2 miss in different rounds, where the second batch is stipulated to have been fetched for non-E ID 8 using the same name. This is a possible producer history with the same stored pick schema. `bind_daily_files` returns `bound`, `ownership_conflict_users` is empty, and `e_arm` attributes both rows to ID 7, reporting **1/2 instead of that member's 1/1**. The stored rows cannot distinguish the two owners. This demonstrates non-identification, not a measured real collision.

**F3 — High: the streak engine fabricates saver continuations and exact full-window metrics from insufficient history.** `streaks.py:46–65,74–105,124–135`.

Continuation is decided solely from the two H endpoints. Intervening M/A rows contribute their kinds but not their reported streaks or a supported saver transition. Every ambiguous A row spanned by such a link is then declared absorbed. This can manufacture exact runs despite explicit incompatible observations. The window routine also ignores the first H link and has no requirement establishing the window's unobserved prefix/suffix or complete entered-round history. Its `exact` describes a chain of retained observations while the output promises the longest streak built in the fixed window.

Synthetic probe, using `_row`/`_obs` from `test_field_products_picks`, one slot per round, capture July 4: May 1 `hit/streak=1`; May 2 `not_hit/streak=0`; May 5 `hit/streak=2`. The output labels the last link `continuation_through_miss`, returns `window_summary.status="exact"`, and calls the attaining run **recoverable, May 1–May 5**. A valid hidden May 4 hit after the May 2 reset produces the May 5 streak of 2, whose run starts May 4. A saver at streak 1 is also unsupported by the project's 10–15 rule. Endpoint equality is not evidence that the May 1 run survived.

Second probe: the only retained round is June 1 `hit/streak=20`. May 1–July 3 returns **`exact`, `longest_exact=1`** with no reasons. A history starting a twenty-hit run on May 13 and observed only on June 1 has the same retained row and a within-window longest streak of at least 20. Conversely the reported streak could be largely carried in. Neither history is excluded by this input. The safe result is a defensible observed contribution/lower bound with the exact window metric unavailable.

The declared “no compensating hidden reset-and-rebuild” assumption does not meet the frozen design's evidence requirement for exact dates or streaks. Calling an assumption `evidenced` is the defect; no real frequency of hidden resets is asserted.

**F4 — High: timestamp unions and omitted pending legs are treated as complete round snapshots without a completeness witness.** `picks.py:113–155`.

All rows with the latest timestamp for a round are pooled across files into one snapshot. Slot-set differences between equal-time files are not conflicts unless the same slot has conflicting content. An older pending second leg disappearing makes `deleted_legs=1` but does not make the round incomplete; only disappearance of a settled leg does. Neither path consumes evidence that the chosen batch was one complete round response or that deletion was established. This violates the explicit unknown-slot-2/deletion rule when such evidence is unavailable.

Synthetic probes: (a) file `a` contains only primary hit and file `b` contains only secondary hit for the same user/round/time, with no shared batch receipt. Resolution returns **`complete=True`, `is_dd=True`, two slots**; two independently partial records have become a complete DD. (b) an older timestamp has two pending legs; the later stored timestamp has only a settled primary, without a completeness/deletion receipt. Resolution returns **`complete=True`, `is_dd=False`, `deleted_legs=1`**. A partial later observation with an unobserved second leg and a witnessed deletion are observationally different cases; the current interface cannot distinguish them. The existing tests deliberately accept (b), so a green suite encodes the disputed assumption.

Keep individual exact grades usable where their identity is supported. DD and streak completeness need a supported whole-round batch. A verified final-grab raw response may provide it; raw/path/timestamp evidence must actually be validated and supplied, not inferred from the number of retained rows. A whole round omitted later may be retained as a positive historical observation, but the flag alone establishes neither deletion nor complete follow-up.

**F5 — High: an integrity failure still produces allegedly valid observed lower bounds from the failed output.** `census.py:125–143,150–165`; `run.py:180–187`.

The gate correctly notices a board hash mismatch or raw/output disagreement. The summary then counts that same unverified parquet and labels its numbers `observed_lower_bound`. Incomplete population coverage and invalid observations require different dispositions. Corrupted, conflicting or duplicated rows are not lower-bound evidence.

Synthetic probe: produce the real fake-transport 420-user grab, whose raw threshold count at 40 is zero; change only the first output parquet's season best to 40. Both `board_output_hash` and `board_rows_equal_raw` fail, but the summary publishes **`basis="observed_lower_bound", ge_40=1`**. Duplicate that altered row and it publishes **ge_40=2**, listed 421. Both purported lower bounds exceed the verified raw population's count of zero. On a hash/content/uniqueness failure, either refuse those summaries or compute them from independently qualified unique raw observations, with conflicting/unverified rows excluded and counted.

Also distinguish the maximum/tie among known values from the field maximum when any best is missing. Probe `[20,18,null,0,0]` yields `max=20`, `tie_at_max=1`, although the null entrant could have 40. Missing values make threshold counts bounded known counts, not “exact census counts.” The missing-value percentile interval itself is defensible (declaration 3 below).

**F6 — High: failed membership checks and an arbitrary acceptance filename do not stop analysis.** `cohort.py:46–65`; `run.py:141–143,156–174,214–218,225–232`.

`allocation` reports failed manifest/allocation checks, but the driver proceeds using re-derived labels while case series A uses recorded A and profile provenance uses recorded identity. The copied manifest hash is likewise diagnostic only. An alternative manifest or mismatched acquisition record can silently define the extension incorrectly. The production arm requires merely that `ACCEPTED.json` exists; it is never parsed or checked against the accepted W1.1 recipe/build. A hash of arbitrary bytes recorded after execution is not acceptance evidence.

Synthetic end-to-end probe: in `_inputs`, replace `early_cohort_sha256` with zeroes, change recorded B from its valid allocation to `[2001,2003,2005]`, and write `this is not an acceptance receipt` to `ACCEPTED.json`. The driver returns **0**, publishes both `manifest_sha_matches_grab=False` and `recomputed_allocation_matches=False`, includes all **4** synthetic production slots, and emits the extension. It does not refuse any failed prerequisite. This probe does not claim the actual published ledger is defective; it proves the reader cannot establish it is reading that ledger.

**F7 — Medium: “same New York date” substitutes for independent historical pick-time context, and equal-time context conflicts silently choose a winner.** `picks.py:69–72,251–273`; `leaders.py:25–27`.

Any same-day nonnull lookup becomes `witnessed`, including the current final-grab lookup. No historical-context witness or source timestamp is required. Same-day capture alone does not establish the team/squad at the relevant pick time. Context fields are excluded from equal-time conflict detection, and composition chooses the last row without reporting their disagreement.

Synthetic probes: a May 1 23:00 UTC row with current BOS/away lookup, no historical witness, is counted **witnessed=1, unknown=0, away=1, top_team_share=1**. If the pick-time context was NYM/home, that number is wrong; both histories fit the stored row. Two otherwise identical same-time observations, one NYM/home and the other BOS/away, resolve slot status `ok` and composition silently reports the latter as witnessed. Preserve slot grades, but refuse unsupported/conflicting context. The bounded fallback is unknown composition; no enrichment is required.

**F8 — Medium: the reported round denominator counts user-dates rather than user-rounds.** `compare.py:117–123,236–238`.

Synthetic probe: E has user 7, round IDs 1 and 2, both on May 1, one graded slot each. The analytical keys are distinct and are accepted. The table reports **rounds=1, slots=2**; extension repeats the same counting rule. Count distinct `(user_id, round_id)` on the selected slots, or explicitly validate/refuse multiple round IDs per user-date before equating these units. The existing comparison tests omit round IDs from their helper arms and therefore assert the user-date convention, not the design's round denominator. This is a schema-boundary defect, not evidence that the real contest has multiple rounds that date.

**F9 — Medium: semicolon serialization breaks supported pre-sanitizer filenames.** `cohort.py:141–142`; `run.py:193–197`.

The binder supports an old raw-name file, but stores its name in a semicolon-separated scalar that the driver splits. Synthetic manifest name `a;b`, with only the legitimate old `a;b.parquet` file, binds as **`bound`, `n_files=1`, `files="a;b"`**. An end-to-end synthetic run then tries `a.parquet` and raises `FileNotFoundError`. Use an actual list/structured encoding for paths, or quarantine this unsupported name explicitly before the first outcome step. Do not serialize arbitrary public names with an unescaped delimiter.

## Required code changes

1. **F1:** Verify each exposure row in its named published Git revision and bind the current recipe/register to those revisions. Refuse dirty executing sources or hash all actual executing dependencies. Build and write a source path/hash manifest, including final-grab identity/path binding, before parsing outcomes. Parse the exact frozen bytes (or staged immutable copies) and refuse any content/listing change. The post-run manifest must agree with that freeze; adding more post-run hashes alone is insufficient.
2. **F2:** Require a unique existing capture/batch-specific user-ID witness for daily attribution, considering possible non-E claimants and sanitized collisions. A May 1 name can nominate candidate files; it cannot certify every appended batch. Quarantine/count unsupported batches or the entire ambiguous member. If retained evidence cannot support the join, leave that member's primary quantities unavailable. Keep all E members in availability.
3. **F3:** Do not merge hit chains through M/A or unobserved history solely because endpoint streaks add up. Require supported intervening transitions/boundaries; otherwise split observed segments, with unavailable exact dates/window maxima. Respect incompatible reported values and saver ambiguity. Require adequate window coverage before `exact`; otherwise emit lower-bound-only/unavailable. The safe minimal implementation can disable exact reconstruction for unsupported histories.
4. **F4:** Select one supported complete round batch rather than unioning complementary equal-time files. Treat competing slot sets as conflict/unknown. Without an existing completeness/deletion witness, mark disappeared pending legs and uncertain slot 2 incomplete for DD/streak summaries. Preserve qualified individual grades and the positive-observation dropped-later flag. Retain representative source file/row provenance in resolved slots.
5. **F5:** Separate incomplete population coverage from integrity/identity/content failure. Refuse summaries from the latter, or use only qualified unique raw observations; never label failed parquet counts lower bounds. Label missing-best thresholds/max/ties as known-value bounds/observed maxima with unknown contributions.
6. **F6:** Fail closed on the manifest SHA, count, allocation and copied-manifest checks before outcomes. Validate the grab's recorded identity/artifact bindings. Parse and verify the W1.1 acceptance receipt against its frozen fingerprint, named outputs and published build identity, and bind the selected bytes to its accepted evidence. Refuse invalid/mismatched receipts before calculating rates. No changes to the frozen ledger compiler are required.
7. **F7:** Require an independent historical context witness and reject/count context conflicts; same-day current lookup alone is unknown. The minimal fallback is unavailable composition on unsupported rows, preserving the coverage count.
8. **F8/F9:** Count actual analytical round keys (or refuse an unsupported round/date mapping); carry path lists structurally rather than splitting arbitrary names. Preserve the existing unavailable/empty-stratum behavior. Add focused regression cases for the demonstrated failures; do not replace the 72-test baseline with tests that merely reaffirm the current assumptions.
