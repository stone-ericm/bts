## New findings

1. **BLOCKER — the new code cache changes application lifetime and accepts the resulting event.** O:143 and O:146 retain each examined CodeType in module-wide `_ENTRY`, including code that is not a declared application boundary. Retaining that code also retains arbitrary application constants, which ruling 12 expressly admits (Plan:144).

   Regression: during the helper call, build a temporary FunctionType from compiler-produced lambda code whose unused extra constant has a finalizer. Call it and discard the function, code and direct constant reference. Send the alert only when the finalizer has not run; otherwise send null. The green helper sends the expected pick. The frozen assertion is identical in the observed/plain twins, and both mutant twins reach the same assertion outcome, so stage comparison does not expose the different boundary values.

   **Measured:** `routes-runs/test_a_code_cache_never_change0/measurement.json` records `constant_released False` observed versus `True` plain, no observer error, and an accepted alert certificate linked to entry/branch/event **2/3/4**. The ordinary application twin sends null; the observer creates the alert condition by retaining the code. This fixture never inspects the observer, replaces a standard-library function, or changes interpreter memory. It is an in-model false event certificate, not an excluded mechanism or an absence claim.

   **Smallest fix:** remove the owner-retaining cache, or key the decision by exact immutable `(co_code, co_exceptiontable)` byte strings and retain only observer-owned metadata. Do not replace the retained-code id cache with an unowned id-only cache: id reuse would need its own protection. Require observed/plain finalizer timing and values to match, and refuse the saved alert certificate. Clearing the cache only after the call phase is too late.

2. **BLOCKER — a public line jump makes the original entry offset readable again.** O:1141 accepts any PY_START at the offset returned by O:146; O:185 scans static jumps/handlers. Neither establishes that this is the frame’s first actual entry. Plan:147 additionally says a second start at the entry offset is not read.

   Regression: install an application `sys.settrace` hook for its own compiler-produced boundary function. The function receives and records the original Cell, then rebinds `text` to the alert. At that later line the trace hook sets `frame.f_lineno` to the definition line. The existing body guard then returns without another send. This code has no static jump or handler leading to the entry.

   **Measured:** `routes-runs/test_a_public_line_jump_cannot1/measurement.json` records a successful public jump, no jump/observer errors, the actual original-Cell receipt, and two recorded boundary events: event **4** is unavailable; event **5** is an alert reread, accepted with entry/branch/event **2/3/5**. There was no second actual alert send. The no-jump control is rejected (`...cannot0/measurement.json`). No observer/stdlib code or native interpreter memory was changed. The current first-offset and target-scan tests are therefore false greens for the broader initial-entry claim.

   **Smallest safe fix:** refuse active or newly installed application tracing for the entire observation window, with enforcement before a trace hook can enter an observer callback. If tracing must be supported, add an independent initial-entry witness, not just static offsets. Frame deduplication helps a frame first seen during this window but does not by itself establish initial entry for an already-running frame. Add that pre-existing-frame variant as a separate regression; it was not measured with line tracing here.
