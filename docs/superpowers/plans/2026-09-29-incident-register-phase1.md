## Rulings (each with its cost if wrong)
1. **Build before plan for Phase 1.** The fixtures and tooling are test code, not production code; Codex reviews plan + code together. *Cost if wrong:* a plan defect surfaces in code review; nothing merges or deploys first.
2. **The causal witness is a trusted external `sys.monitoring` observer**, as design v3.2 §9.3 now permits (Codex r3 supplied the amendment; it did not approve the r3 implementation, see Task 3). *Cost if wrong:* a certificate built on an incomplete recorder overstates absence; every coverage limit is therefore reported as `unavailable`, never as absence. **Rev 6 (Codex r5 #1):** the observer tracks each declared binding at every store on its path: CPython dict watchers on the module and class namespaces from `sys.modules` down, and a function watcher for `__code__` replaced in place. Any other namespace shape is a coverage gap. A call that cannot be attributed to one binding's current value has an unavailable identity. **Rev 7 (Codex r6 #1, #2, #4, #5, #6):** the path starts at sys's own namespace, so replacing sys.modules is a watched store. Namespaces are accepted only under exactly standard dispatch (exact `ModuleType`; a class whose metaclass is exactly `type`), and every path owner's exact type is re-checked at every function start while boundaries are observed. A code object shared by several live functions leaves its call unattributed. Callables are recognised by exact type identity. Every live interpreter thread is counted. A failed start releases everything it acquired. **Rev 8 (ruling 10; Codex r7's wording corrections):** the observer supports POSITIVE witnesses only. Exact `ModuleType` and exact-`type` classes remain the only watched shapes, but exact type does not make the raw namespace all of attribute lookup (module `__getattr__` fallback, inherited class attributes, descriptor dispatch). Sampling owners at Python function starts does not show that no transient dispatch change occurred between them, so the per-start re-check is removed rather than relied on. A call reached through lookup the recorder does not observe is not recorded, which can only miss an event. An unverified mock call implementation (its effective `__call__` is not the standard one, or its class changed) is unattributed. Application callbacks that observation could run (an audit hook added after the trusted bootstrap, automatic collection, a signal handler) make the interval unavailable. The thread census, an absence-only obligation, is removed with absence.

6. **Contemporaneity (design §3) — REPLACED after Codex phase-1 r4 with Codex's text, verbatim:** *"Qualify each report-to-occurrence and report-to-fix-step citation independently. A fix-step report establishes only the cited mitigation, installation or verification and cannot establish an observed incident. An observed incident needs a qualified primary witness to a contract deviation. For a continuing condition, the report must describe the condition as still observable at a supported time; absence of a known end is not evidence of continuity. Use the earliest supported event that actually ended the cited condition, restricted to its own links. A code install or partial mitigation ends that condition only when the evidence supports that relationship. Preserve inferred onset and uncertain end bounds explicitly."* **Structural rule** (`records.py`):
   - Each CITATION of a report by a dated claim (occurrence bound or fix step) qualifies on its own. The report must be written no earlier than the claim's earliest instant (strictly before = refused) and within 48 h after its latest instant.
   - An open-ended claim anchors nothing.
   - A continuing condition is witnessed only at its supported `observed` times, never through an unknown end.
   - An observed incident needs an onset, observed-time or machine-detection claim of an occurrence that cites either a primary machine observation or a qualifying primary report. Awareness and fix steps are not witnesses.
   *Cost if wrong:* a report can support only the claims whose time it could have witnessed; genuine but badly dated reports are refused until their claims are dated.
7. **Expected-failure connection kinds (amended after Codex phase-1 r4 #3):**
   - `return` / `reads` prove a VALUE MATCH, not dataflow: the last complete return of the declared function, or the complete read-backs after the entry (zipped with equal cardinality), equal the oracle's actual.
   - Status `value_match` counts only with the fixture review recorded in the registry. That review states which call or selection the oracle consumes.
   - `derived` → `exception_shape`, also only with a recorded review.
   - Anything else is `unmatched`; a truncated or otherwise incomplete observation never matches.
   *Cost if wrong:* the dataflow claim rests on the recorded review, stated as such.

11. **Fix r9 as a class: observation runs no application code (Eric, 2026-10-01: "Fix the class, then r10").** Codex phase-1 r9 measured accepted certificates while the observer ran application `__eq__`. The cases were a `str`-subclass key colliding with `__dict__` or `__module__` in a class namespace (#1), and one colliding with `text` in a standard Mock call's keyword dict (#2). Session import records showed the same pattern after the interval (#3). The design already required observation that runs no application callback (§9.3). The fix states the rule for the whole class rather than refusing the measured instances, as `certify.COVERAGE["observation"]`. Inside the call phase, the observer hashes, compares or dispatches only on values it owns or has type-checked as exact builtins:
    - **Dicts.** A dict the observer reads is walked item by item (`observer._lookup`). A dict holding any key that is not an exact `str` is **unsupported, never skipped**, because skipping the key could miss the entry that real lookup finds. Through such a dict:
      - a binding path is a coverage gap;
      - a mock's effective `__call__` reads unverified;
      - a keyword identity reads unavailable.
    - **Class metadata** (Codex r10 part 2 #3, verbatim). A heap class's `__module__` is read by iterating its raw namespace. An instance's `__dict__` is read by directly calling the standard C getset found by raw MRO namespace iteration; there is no generic attribute lookup. An unsupported class namespace ends the search.
    - **Stores.** A store into a watched namespace through a key that is not an exact `str` invalidates like a clear: a gap, the chain cut there, and nothing current until a per-key store re-resolves it. That re-resolution first reads the changed namespace's whole key shape, so it happens only once the namespace holds no such key (r10 part 1 #2). Because a store's callback runs BEFORE its change, a re-resolution can still read a namespace another thread is about to change (r10 part 2 #1). (Codex r11 #2, verbatim:) A store which has passed its callback may commit during a later attribution check. Callback serialization alone does not establish a linearization point for the complete binding-path read. Since ruling 12, the attribution read runs only while the observed thread is the interpreter's only thread, so no store is pending then. So one lock serializes every binding-state transition and every attribution read, and each watched store's callback takes it before its change. A call is attributed only if, AT THE CALL, the binding still resolves to the bookkept current value through watched namespaces that are all supported (`_current_now`, read under that lock). The lock serializes watcher bookkeeping and attribution checks; it does not cover the C-level commit (Codex r11 #2).
    - **Code objects.** A code object's filename or name that is not an exact `str` reads as unnamed; no hash or path method runs on it. Code objects themselves are never hashed or compared. A code object's hash and equality reach its `co_name` and `co_consts`, which crafted code may make application objects. The observer's maps key them by id and hold the object (`_code_key`; my own review and r10 part 1 #1).
    - **Session import records.** Only exact modules are read: namespaces through the descriptor, `__file__` by iteration. A missing `__file__`, or one that is not an exact `str`, is recorded unavailable and never resolved. Any `sys.modules` key that is not an exact `str` makes the whole record unavailable: hashed lookup may resolve it as any module name, whatever its text. Nothing is omitted, and `runner.gate` refuses every unavailable record (r10 part 1 #3).

## Found in my own review before r15
- **The function watcher changed the application** (cause of r14's segfault). CPython calls function watchers for every function's creation and destruction. A lambda freed after a failed C call fires one while its exception is pending; the ctypes trampoline returns a result with an exception set; CPython replaces the application's exception with `SystemError`. Measured at `e927a75`: `sorted([1, "a"], key=lambda x: x)` raised `SystemError: error return without exception set` under a running observer. A full defence run took an application's `except SystemError` branch only when observed, and sent the alert there; it was refused only because `_on_func` recorded the converted error as an observer error. A trivial ctypes function watcher, with no observer, crashes `pq.write_table` in Cython's error path. `f072503` removes the function watcher; a held function's swapped `__code__` is registered at the new code's first start, only while alone (`observer._swapped`; O98, O99; O19 retired).
