## Production prerequisite (found 2026-10-06, by reading code)
§2 admits a row only if:
- its archived write time is strictly before the game's run-known start minus `SUBMISSION_CUTOFF_MIN`, **and**
- an archived pregame-status observation at or before that write establishes eligibility.

The served-slate archive (`src/bts/slate.py`, `bts_slate_v1`) records `written_at` and the rows' `game_pk` / `batter_id` / `p_game_hit` / `projected`. It does **not** persist each row's `game_time` or the schedule `status`, although the prediction rows carry both (`src/bts/model/predict.py`, the lineup slots). Under §2 every 2027 row would then be excluded, and 4a would be inconclusive.

**Prerequisite P1:**
- **The change:** persist `game_time` and `status` (the schedule's `detailedState` as fetched in that run, before the write) in `ROW_COLUMNS`, and bump the schema to `bts_slate_v2`.
- **Process:** this is production code. It is reviewed until SIGN, the concrete change goes to Eric under D7, and it is deployed before 2027 contest date 1.
- **Overlap:** it overlaps with the rank-3 shadow archive (registration rank 3 §5), whose run snapshots also need run-known game time and pregame-status evidence. The two are kept as separate changes under D2.
