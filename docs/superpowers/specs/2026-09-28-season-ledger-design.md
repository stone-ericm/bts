# Season 2026 canonical ledger (W1.1) — design v3

**Date:** 2026-09-28 · **Plan item:** W1.1 (`docs/superpowers/plans/2026-09-14-season-wrap-plan.md` §W1.1, approved 9/22) · **Brief:** confirmed by Eric 2026-09-28 · **History:** v1 → Codex design r1 BLOCK (`docs/audit/2026-09-28-season-ledger-codex-design-r1.md`); v2 (never committed; superseded in the same session — r2 cites its section numbers) → design r2 BLOCK (`docs/audit/2026-09-28-season-ledger-codex-design-r2.md`); this v3 answers r2 (§13) · **Status:** v3 → Codex design r3 → Eric's spec review → implementation plan → build.

## 1. Purpose and Phase 1 success
One audit-grade fact base for the season's **production** decisions, so the wrap's reads and memos stop re-deriving from raw files. Built once, deterministically, from a sealed evidence bundle; not a nightly job.

Phase 1 (plan W1.1's minimum pass) delivers: production source observations, qualified contest evidence matched to specific games, local slot results as recorded, an explicit comparison vocabulary, and an honest reconciliation. It does **not** grade cached game feeds (deferred, §12) and makes **no negative claims it cannot prove** (entry absence, finalization, history completeness default to unknown).

**Success:** (a) every source occurrence is accounted for — emitted, excluded with a reason, or quarantined — with cardinality and anti-join checks; (b) the only authoritative BTS outcome is a qualified contest slot grade matched to a selection; (c) the reconciliation reports recipe membership as exact, partial, hypothesis or unrecoverable, never forced; (d) compiling twice from the same bundle yields byte-identical outputs; (e) §11's fixtures run raw synthetic source files through the real parsers.

## 2. Scope
**In:** production decisions for season dates 2026-03-25 → 2026-09-27. **Out:** cached-feed grading and capture chronology, MLB's current record, shadow v1/v2, skip-policy shadow, D8 research, recipe epochs, slate binding (all §12); field data from the grabs (W2); any change to production code or files. The completed P-01 read and its frozen recipe are untouched.

## 3. Evidence: acquisition, then offline compilation
`acquire` (read-only against sources) copies every input into `data/hetzner_results/season_2026_ledger_evidence/v1/` (archive backup set) with `manifest.json` listing, per input, the logical relative path, sha256, size, source path, source mtime and acquisition time. An input the acquisition expected but did not find is listed as `missing` — valid evidence of absence. `compile` runs with no network, reads only the bundle, and refuses a file declared present that is absent or hash-mismatched (not a declared `missing` entry). A later acquisition is a new bundle version. Outputs use a fixed schema (explicit types, nulls preserved, UTC ISO strings), stable ordering, relative paths, fixed parquet writer settings, and record the builder version and `uv.lock` hash.

**Inputs (Phase 1 needs no network):** from the frozen W0.7 snapshot `final-20260928/`: pick files `data/picks/<date>.json` (156, 3/29 → 9/18); archived candidates `data/picks/<date>/<prefix>_<stamp>.json` (27 `deferred_fallback`; the writer also defines `stale_pick` and `refused_delivery`, none present); decision files `<date>/decision.json` (92; v1 from 6/23, v2 from 8/09, v3 from 9/03); scheduler state `<date>/scheduler_state.json` (167); lineup-evolution logs `data/picks/lineup_evolution_<date>.jsonl` (append-only, written by `save_pick`); `archive/`, the three late-May streak-repair archives, `streak.json`, `account_state/*` incl. every raw line of `contest_ledger.jsonl`; BTS static captures `data/leaderboard/static_snapshots/{rounds,units}/` (units carry `feedId`, from 2026-07-04) and the 9/27 grab's `raw/static/` (rounds, players `playerId` ↔ MLB `feedId`, units, squads); the scheduler journal and `cron.log` (corroboration only). Plus one acquisition-time fetch of MLB **schedule** responses for every season date (historical game lists, including postponed and suspended entries), stored with fetch time — used only for the evidenced game inference in §6.

## 4. Source occurrences and observation tables
Every source record is an **occurrence** with identity (relative path, record/slot locator, content sha256) — two byte-identical files at different paths are two occurrences. Occurrences are parsed losslessly (absent / null / zero kept distinct) into:
- **O1 pick files** — per slot (primary / double_down): batter_id, batter_name, team (as recorded at pick time), game_pk, game_time, lineup_position, projected_lineup, pitcher_id, p_game_hit; day `result`; per-slot `slot_results`; delivery fields as written (`notification_sent`, `notification_id`, `notification_channel`, `delivered_at`, `delivery_attempted`, `bluesky_posted`, `bluesky_uri`); provenance fields as written.
- **O2 archived candidates** — the same, plus prefix, reason and archive time.
- **O3 decision files** — all fields as written, schema version.
- **O4 scheduler state** — `pick_locked`, `pick_locked_at`, `committed_pick_written`, `final_skip_candidate`, `skip_notified_at`, `delivery_refusals`, `fallback_refreshes`, `result_status`.
- **O5 lineup evolution** — each appended observation (thin: batter, game, probability, time); used only as history evidence.
- **O6 contest** — one row per (ledger line × round × slot), plus a round row for slotless rounds: line number, `recorded_at`, `source_date`, `active_streak`, `best_streak`; round `roundId`, `result`, `streak`, `streakIncrease`; slot `number`, `unitId`, `playerId`, `result`, `hits`, `atBats`.
- **O7 unit captures** — (unitId, feedId, roundId, capture file) per capture; conflicting mappings for one unitId are kept, not collapsed.

## 5. Row kinds and day status
| Evidence for a date | Rows emitted | Notes |
|---|---|---|
| Decision file, action `single`/`double` | `selection` row(s) for the named primary (+ double-down) | canonical; if the surviving pick file names a different selection: `finalization = unresolved`, both views kept, the pick file's delivery/probability/result never attached to the decision's selection |
| Decision file, action `skip` (end-of-day skip shape: `scoreable = false`, no committed pick) | one `skip_day` row | the declined `primary` candidate is an observation only, never a selection |
| No decision file (before 6/23), surviving pick file | `selection` row(s) with `finalization = pick_file_only` | commit evidence (`commit_status`): `delivered` (era predicate §9), `entered` (contest match §6), else `unconfirmed` |
| Scheduler state with `final_skip_candidate` only (no decision file) | one `unfinalized_day` row | intent, not a skip; a skip candidate alongside `committed_pick_written` is never a skip |
| Archived candidate(s) only / attempts without a surviving final record | one `unfinalized_day` row | candidates are observations |
| No evidence | one `unobserved_day` row | never inferred to be a skip |
| Contest slot with no matched local selection | a `contest_only` row | identity (date, roundId, unitId, playerId, slot `number`); local slot role `unknown` |

**History status** per selection: `complete` only when every source that can hold an earlier revision for that date is present and consistent (decision file, pick file, scheduler state, lineup evolution with no other selection logged that day); `known_incomplete` when evidence shows an earlier selection whose full record is gone (e.g. a lineup-evolution entry or archive naming another batter); otherwise `unknown`.

## 6. Contest evidence
**Qualification.** A ledger line qualifies when it parses, carries `recorded_at` and a `predictions` list, and each round has `roundId` and `result`; slots need `unitId`, `playerId` and `result`. Lines are ordered by (`recorded_at`, line number). For each slot identity (roundId, unitId, playerId) the ledger keeps `first_seen`, `last_seen`, the last qualified values, and any change between lines; a slot or round missing from a later line keeps its last positive observation, flagged `dropped_later` — a newer omission never erases an older positive. These observations are "last observed official grade at time T", not a finality certificate.

**Matching a contest slot to a local selection** (never by slot `number`): round → date via the rounds capture; `playerId` → MLB batter via the players lookup (identity is stable across trades); game via (1) the unit captures (`match = evidenced`) when the unit has exactly one `feedId`; else (2) for a local selection only: the selection's own recorded `team` at pick time and the acquired historical schedule for that team and date, counting **every** listed game including postponed and suspended entries — exactly one game and equal to the selection's `game_pk` gives `match = inferred`; anything else is `ambiguous`. Contest-only slots without a unit mapping stay `unmapped`. Only `evidenced` and `inferred` matches transfer a grade.

**Entry status:** `confirmed` (a qualified contest slot matched), otherwise `unknown`. Phase 1 makes no "not entered" claim.

**Round semantics:** round labels `hit`, `not_hit` (a miss that ended a streak), `void` (a miss at streak 0), `used_mulligan` (a miss the saver absorbed) are kept as `contest_round_result` and are never copied onto legs. Streak before/after and saver availability are emitted only where the evidence chain is explicit (both rounds present in one qualified line with `streakIncrease` consistent); otherwise `unknown`. `saver_transitions.jsonl` rows are reported as attempts (including rejected ones), not as consumption times.

## 7. Outcomes and comparison
- `contest_slot_grade_raw` / `bts_outcome` — the matched contest slot's `result`; `bts_outcome_status` = `graded` / `matched_ungraded` / `match_ambiguous` / `unmapped` / `unknown`.
- `local_slot_result_raw` — `slot_results[slot]` exactly as written. `local_day_result_raw` — the day `result`. `local_slot_result_derived` — only for a selection whose own record is a single pick (no double-down in that record), bound to that record's day result, with `derivation_source`; otherwise null. Double-down days without `slot_results` leave both legs null.
- **Normalization (closed table):** local `hit` → HIT, `miss` → NO_HIT, `void` → HOLD; contest slot `hit` → HIT, `not_hit` → NO_HIT, `void` → HOLD; anything else → UNKNOWN. HOLD means the slot neither extended nor broke the streak (a Pass or a voided slot); round-level `void` is not part of this table.
- **Comparison:** only slot-level, known, same-selection, same-game values; day aggregates and UNKNOWN never compared. Flag `local_vs_contest_disagreement` (the C-03 pattern). No flag asserts when a change happened.

## 8. Reconciliation (acceptance)
Three separate tables: (1) **source-occurrence accounting** — every occurrence from §4 (including decision-only selections, scheduler-only observations, archives, lineup-evolution entries, every contest line) ends `emitted` / `excluded(reason)` / `quarantined(reason)`, with counts and anti-joins; (2) **selections** — deduplicated canonical rows; repeated contest snapshots never become extra picks; (3) **recipe membership**:
- The **9/11 scorecard** (141 primaries / 82 DD legs) is recorded only as prose (memory `bts_index`: production pick files 3/29 → 9/10, primary slot, hit/miss). Rerunning that prose on the frozen files is a `hypothesis` reconstruction: files could have changed between 9/11 and the 9/28 freeze, and each record's evidence interval is shown (C-03's 8/20 flip landed 8/26, before 9/11, so the scorecard saw the miss). Historical per-record membership stays `unknown` unless independent evidence pins it.
- The **9/14 naive tally** (191 primaries / 157 DD legs) has no recorded recipe. A short list of candidate rules is written into the implementation plan before any count is computed; every rule that reproduces both totals is reported as `matches published totals; historical membership unverified`, all matching alternatives retained. If none matches: `unrecoverable`.
- Recipe outcomes and canonical outcomes are separate columns. Golden synthetic fixtures fail the build if one occurrence is omitted, duplicated, or matched to two games, and include two different rules with identical totals.

## 9. Field contract (Phase 1 canonical columns)
Keys: `row_kind`, `date`, `round_id` (nullable), `slot` (`primary` / `double_down` / null), `selection_id` (date, slot, batter_id, game_pk; null for day rows), `finalization`, `commit_status`, `history_status`. Pick: `batter_id`, `batter_name`, `team_at_pick`, `game_pk`, `game_time`, `lineup_position`, `projected_lineup`, `pitcher_id`, `p_stated` (all nullable). Decision: `action` (single / double / skip / null), `action_source_raw` + `action_source` (mdp / heuristic / unknown), `objective` (v1/v2 files → `reach57` per `daily_decision.decision_objective`; v3 → as recorded; invalid → `unknown`), `degraded_reason`, `decision_streak`, `decision_state_source`, `decision_state_status`. Timeline (event times; null when unobserved): `predicted_at` (run_time), `locked_at`, `delivery_attempted_at`, `delivery_confirmed` (bool / null) with `delivery_basis`, `entry_observed_at` (first qualified contest line containing the slot — an observation time; the entry event time itself is unobserved in Phase 1). Delivery predicate by era: decision `delivery_status = delivered`; else `delivered_at` present; else `notification_sent` with a `notification_id` (DM); else `bluesky_posted` with a `bluesky_uri` (legacy public post) — an attempt alone is not delivery; conflicting private/lock evidence is kept as a flag. `game_eligibility`: `ineligible_evidenced` (voided / postponed slot), `refused_evidenced` (a recorded delivery refusal), else `unknown`. Contest: `entry_status`, `match`, `contest_round_result`, `streak_before`, `streak_after`, `saver_available_before` (all nullable). Outcomes per §7. Journal lines only corroborate; a journal-only value becomes a note, never a field.

## 11. Fixtures (raw synthetic files through the real parsers)
Rows: decision `double`; decision `skip` carrying a declined candidate (→ one `skip_day`, no selection); scheduler skip candidate only (→ `unfinalized_day`); skip candidate plus committed pick (→ not a skip); archive only; decision-only committed selection with no pick file; decision and pick file naming different selections (→ unresolved, no attachment); no evidence (→ `unobserved_day`); a contest-only slot. History: lineup evolution naming another batter (→ `known_incomplete`); missing history (→ `unknown`); a discarded double-down preview followed by an evidenced single. Contest: null `hits`/`atBats`; a round growing between lines; a slot dropped later (older positive kept); a malformed later line (not qualified); mapped and unmapped slots in one round; a saver-absorbed miss; a partial-void double-down; slot order differing from ours. Matching: unit captured (evidenced); a traded player (pick-time team differs from the current lookup → the pick-time team is used); a doubleheader; a postponed plus a played game on one date (→ ambiguous); conflicting unit captures. Comparison: local `miss` vs contest `not_hit` (agree); `void` vs `void` (HOLD); a double-down day miss with a hit primary (no leg disagreement from the day aggregate); the C-03 pattern (disagree). Versions: decision v1, invalid v3 objective, a lock without delivery confirmation, a legacy public post as the only delivery signal. Accounting: duplicate bytes at two paths; two rules with identical totals; an omitted / duplicated / double-matched occurrence (→ build failure). Determinism: relocated bundle root, reordered discovery, a declared-present file missing or changed (→ refusal) versus a declared `missing` entry (→ accepted).

## 12. Later increments (each separately designed and accepted)
Cached-feed grading with a new audit grader (hit / at-bat-or-sacrifice-fly / pass rules; completeness checks for boxscore and plays; suspension boundary; event table incl. sacrifice double plays; unknown on incomplete input) and capture chronology that separates proven capture identity from "mtime/log suggest"; MLB's current record as a dated evidence version; shadow v1/v2 and skip-policy shadow; D8 research through `research_sidecar_state`'s acceptance checks; recipe epochs from supported components with per-component unknowns; slate binding only where evidenced. **Recorded for W1.5 (from r1):** production's `grade_pick_in_feed` returns `miss` for a walks-only or did-not-play batter and treats any pre-suspension plate appearance as a miss, where BTS calls these a Pass.
