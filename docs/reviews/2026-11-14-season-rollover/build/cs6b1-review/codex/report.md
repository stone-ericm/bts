# CS6b-1 adversarial review

## Verdict

**BLOCK** for `0e0c49a3` against `1bf518a2`. Three production findings affect startup cancellation, refusal detection, and the refusal journal.

## Blocking findings

1. **B1. A real operator SIGINT during the morning send is swallowed.** At 10:00 ET on a required DM day with a 16:10 first target and missing contest state, a second thread sent actual SIGINT to the scheduler process while the captured transport was waiting. HEAD logged `Morning state check failed: ''` and ran all six lineup checks. The archived base received the same signal at startup while waiting for the first target and exited `run_day` before a check. The default Python signal handler raises `KeyboardInterrupt` in whichever code is running. The new outer catch consumes it, and either inner stderr catch can also consume it if it arrives there. Preserve CLI cancellation by identifying signal-origin interrupts at the scheduler entry point and propagating them through all three advisory catches while retaining isolation for exceptions from the work itself. A scoped SIGINT handler that raises a distinct `KeyboardInterrupt` subclass can supply that distinction and restore the original handler on exit. [Boundary](../../src/bts/scheduler.py#L2931) · [stderr catches](../../src/bts/scheduler.py#L115) · [actual signal replay](fault-probe.log)

2. **B2. An unreadable commit record can abort the advisory before the required read.** An otherwise eligible 10:00 DM start with missing contest state, no pick file, and a decision JSON with an accepted schema, today’s date, `scoreable: true` and `action: []` emitted only `Morning state check failed: "unhashable type: 'list'"`. It reached the first prediction without the morning CRITICAL. A file containing 20,000 nested arrays also suppressed the DM in either record slot. Actual invalid UTF-8 files took the required absence path and sent. Add `TypeError` and `RecursionError` to the morning decision-read recovery, and `RecursionError` to the morning pick-read recovery. This keeps the recoveries local to the advisory. [Startup reads](../../src/bts/scheduler.py#L140) · [Decision parser](../../src/bts/daily_decision.py#L131) · [On-disk reproductions](fault-probe.log)

3. **B3. A CRITICAL send failure republishes the full refusal as a multiline traceback.** With no season switch and a captured transport raising `OSError`, the new morning call logs the bounded line, then the stock dispatcher logs the active `ContestStateError` as the transport failure’s exception context. The real missing-switch refusal reappears verbatim with all recovery commands and paths. A second replay with a 1,040-character multiline non-ASCII refusal also reproduced the entire raw text and final sentinel. The transport received the exact short DM body. Exit the `except ContestStateError` handler before calling the dispatcher, carrying the bounded diagnostic forward and preserving the existing transport-failure log and retry banner. [Call inside handler](../../src/bts/scheduler.py#L155) · [Dispatcher traceback](../../src/bts/health/alert.py#L256) · [Real refusal](day-head-eod_failed.json) · [Long refusal replay](message-probe.log)
