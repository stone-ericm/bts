# Blocking findings

**B2 — error formatting executes metaclass/name-string hooks instead of reliably raising `ValueError`.** `src/bts/picks.py:691` evaluates `type(date).__name__` and formats its result. The exact-type gate protects `season_of_date`, not this expression.

- Concrete input: `BadDate()` from `r2_attack.py`, whose metaclass overrides `__getattribute__` to raise `RuntimeError` when asked for `__name__`. On a real directory containing `{"season":2027,"streak":5}`, `season_of_date(D)` returns None with no hook calls; real `update_streak([True], directory, date=D)` invokes the hook and raises **RuntimeError**, not the amendment's required **ValueError**. All state readers/writers are guarded, so this is specifically the rejection message, before state I/O. Exact before/after bytes are in `r2-attacks.json`.
- Further demonstrations at the same line: a metaclass returning a str subclass for `__name__` causes its `__format__` to raise **SystemExit**; another writes the review-directory sentinel before raising; another sleeps 60 seconds. The last child prints the helper's safe None result and then stalls in `update_streak`; only that child is killed after two seconds. A catch around formatting cannot undo the I/O or stop the blocking hook.
- **Smallest fix:** obtain the stored name through the builtin type-name descriptor, then flatten it to native str before formatting, instead of doing ordinary attribute lookup. For example, the non-string branch can use `"<" + str.__str__(type.__dict__["__name__"].__get__(type(date))) + ">"`. `r2_minimal_fix_probe.py` verifies a local function copy: both metaclass and stored-name-subclass traps produce the required ValueError, zero hook calls and identical streak bytes. No tracked source was edited.
- These values cannot come from ordinary CLI text/JSON, and no matching constructor was found in `src`/`scripts`. This is nevertheless a BLOCK under the brief's explicit exception: it makes the amended **L4 promise false as written** (“anything else … refused … with ValueError before any I/O”). It is not a claim of a normal command-input exploit.
