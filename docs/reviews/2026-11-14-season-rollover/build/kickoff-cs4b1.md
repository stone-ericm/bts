## Why
The automatic contest observation (`account_state/contest_streak.json`, written by `bts fetch-contest-streak`) does not say which season it belongs to, and nothing in the code can tell: nobody has seen what MLB's endpoints return across a season boundary (ruling R23). The ruling that replaced inference (R24): **an automatic observation is used for a live pick only after the operator has looked at what the endpoints return this season and switched that season to automatic.**

This change set builds the first half of that: the switch file and the commands that show and set it, and a fetch that (a) records every successful reading in the ledger, (b) writes the automatic observation ONLY when the season is switched, stamped with the season and with the identifier of that switching, and (c) rejects two malformed responses it accepts today. It does NOT change which observation any decision uses: the live gate that refuses an unstamped or mismatched automatic file, and the `revoke` command, are change set 4b-2. **Nothing from change set 4a onwards may be deployed before change set 6.**

## Definitions
- **Y** is the calendar year, in `America/New_York`, of an operation's captured `now`.
- **One clock per operation.** Each `season-contract` subcommand captures ONE timezone-aware `now` at callback entry. The fetch captures ONE after its local imports and BEFORE authentication (before `load_session_cookies`). Its ET year Y supplies the observation's season, the ledger's season, the switch evaluation, and BOTH the `source_date.year == Y` saver gate and the saver helper's `season` argument. Its UTC instant supplies the observation's and the ledger line's `recorded_at`. It replaces the three existing clock reads that serve those purposes. The alert helper's, the success status record's and the saver helper's own timestamps keep their clocks. The ledger counts use prediction rows and mapped dates, no clock.
- **Timestamp grammar:** as in change set 4a.
- **The switch file** is `account_state/season_contract.json`. It is **valid** when, checked in this order (the first failure is the one reported, by number): (1) it is readable, UTF-8, JSON and an object (`_UNREADABLE` handling, as change set 1; a path that exists by `lstat` but cannot be read, including a dangling symlink, fails here); (2) `schema_version` is exactly `"bts_season_contract_v1"`; (3) `season` is present and `type is int`; (4) `status` is exactly `"automatic"` or `"revoked"`; (5) `activation_id` is present and is a `str` of exactly 32 characters from `0-9a-f`; (6) `switched_at` is present and is `null` or in the timestamp grammar, and not `null` when `status` is `"automatic"`; (7) `revoked_at` is present and is `null` or in the timestamp grammar, and not `null` when `status` is `"revoked"`; (8) `note`, if present, is `null` or a `str`. Other keys are ignored. All eight are checked before the season is compared with anything: a malformed file for another season is corrupt.
- **Switch state**, decided by ONE function in a new module, `bts.season_contract.switch_state(picks_dir, now, *, season=None)`: it validates one snapshot of the file with the eight ordered checks, THEN compares its season with the inspection season (the keyword, defaulting to `now`'s ET year Y; only `status --season` passes it). It returns one of `absent` (only `FileNotFoundError` from `lstat` means absent), `corrupt` (any other `lstat`, read, decode or JSON failure is check 1; carries the failing check's number and text), `other_season`, `revoked`, `automatic`; for the three valid states it carries the whole validated snapshot, which `status` and `enable`'s carry-over reuse without re-reading. **Season Y is switched** exactly in the state `automatic`.
- **Commands:** every `season-contract` subcommand accepts `--picks-dir` (default `data/picks`, ordinary `click.Path` parsing); `--season` is an integer, required for `enable`, optional for `status`.
- **A stamped automatic observation** is `contest_streak.json` whose `schema_version` is exactly `"bts_contest_streak_auto_v2"`: the `auto_v1` properties plus `"season"` (the fetch's Y) and `"activation_id"` (the switch's, at the moment the fetch read it).
- **Application state:** for the selected picks directory P, everything under `P/account_state/` and `P.parent/health_state/`. Temporary files of the atomic writers are part of the permitted replacement. The saver helper's lock and audit files are permitted ONLY when row 4 invokes the saver helper; `status` creates and writes nothing; `enable` changes only the switch file.

**Known limits, by design (state them in the handover, do not work around them):**
- **No live protection yet.** After this change set a live decision still accepts whatever automatic file is on disk, stamped or not, matching the switch or not. Change set 4b-2 adds the refusal. Not deployable alone.
- **`enable` is the operator's statement** after looking at `status`; the code does not verify what MLB's endpoints mean.
- **While the season is not switched the automatic file is frozen.** Health checks that read it (coverage lag, source date) see an ageing file on a day with no dated observation; that is the state change set 4b-2's refusal and change set 6's alerts address.
- **No lock.** `enable` racing a fetch: the fetch stamps whichever `activation_id` it read. Last replacement wins. The commands report the snapshot they read or wrote, not the state of the path afterwards.
- **A reading rejected by row 3 leaves no ledger line.** The ledger records successful readings only.
