## Blocking findings

- **B1 — `bts season-contract status` prints both `ledger: readable; …` and `ledger: unreadable; …; counts unavailable` when a decoded ledger row raises `RecursionError` during rendering (`src/bts/season_contract.py:169–182`, Row 1(f)):**
  - **Concrete input:** `account_state/contest_ledger.jsonl` containing a valid row `{"recorded_at": "2027-07-15T12:00:00Z", "active_streak": 7}` followed by `'{"active_streak": ' + '[' * 9985 + '0' + ']' * 9985 + '}\n'` (any nesting depth in the ~3–5 frame gap between `json.loads` and the nested generator `repr()` at the caller's stack depth; `9985` via CLI entry, `9990` via direct `CliRunner`).
  - **Wrong production outcome:** `json.loads(line)` at `src/bts/season_contract.py:171` succeeds; line `177` appends `ledger: readable; rows: 2; bad lines: 0`; line `180` enters two nested generators (`for row in rows[-10:]` → `for key in keys`), prints the first row, and hits `RecursionError` inside `repr()` on the second row; line `181` (`except _UNREADABLE as exc:`) catches that per-line `RecursionError` and appends a second, contradictory `ledger: unreadable; unavailable: maximum recursion depth exceeded while getting the repr of an object; counts unavailable` header. Row 1(f) requires mutually exclusive `absent` / `readable` (counting per-line `ValueError` or `RecursionError` as `bad lines`) / `unreadable` (one diagnostic line, counts unavailable).
  - **Smallest fix (`src/bts/season_contract.py:168–180`):** Format each row string inside the per-line `try … except (ValueError, RecursionError):` loop (`rows.append("  " + "; ".join(f"{key}={row.get(key, '—')}" for key in keys))`) before appending `ledger: readable`, then `lines.extend(rows[-10:])`.
  - **How demonstrated:** Reproduced in `probe_2c_switch_enable_status.py` (`probe2c.log`), in a clean subprocess running `from bts.cli import cli; cli()` (`probe_5b_real_cli_and_adopt.py` / `probe5b_summary.json`), and pinned in `adopt/test_season_contract_cs4b1_adopt.py::test_b1_status_ledger_line_repr_recursion_error_never_emits_double_ledger_header` (fails on `28ae3aa9`; passes on scratch-patched `src/`).

- **B2 — `bts season-contract status` misclassifies a JSON boolean `"season": true`/`false` in `saver_state.json` as `another season` instead of `invalid` (`src/bts/season_contract.py:155–159`, Row 1(e)):**
  - **Concrete input:** `account_state/saver_state.json` containing `{"state": "used", "season": true}` (or `"season": false`).
  - **Wrong production outcome:** `src/bts/season_contract.py:157` checks `isinstance(raw.get("season"), int)` rather than `type(raw.get("season")) is int` (unlike `season_contract.py:44` and `contest_state.py:262`). Because `isinstance(True, int)` is `True` and `True != 2027`, `status` prints `saver: unavailable (another season); season: True; reads uninitialized`, telling the operator an invalid boolean-season file is a valid flag from another season, violating Row 1(e) (`whether it is absent, invalid or for another season`).
  - **Smallest fix (`src/bts/season_contract.py:157`):** Change `and isinstance(raw.get("season"), int))` to `and type(raw.get("season")) is int)`.
  - **How demonstrated:** Reproduced in `probe_2c_switch_enable_status.py`, via real CLI subprocess in `probe_5b_real_cli_and_adopt.py` (`probe5b.log`), and pinned in `adopt/test_season_contract_cs4b1_adopt.py::test_b2_status_saver_boolean_season_classified_invalid_not_another_season[True/False]` (fails on `28ae3aa9`; passes on scratch-patched `src/`).
