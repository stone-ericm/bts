## Why
Change set 4b-2 made a LIVE decision refuse an automatic contest observation the season switch does not cover. But "live" is a configuration setting: `_contest_state_required(config)` is true only when `scheduler.contest_state_required` or `health_checks.contest_state_expected` is set. `config/orchestrator.example.toml` has both off, with `pick_delivery = "public"`. A box restored in March with picks going out by DM and neither setting on would pick on last season's contest streak with no refusal and no alert: the hazard the whole build exists to close. Separately, `bts run` (still installed by `scripts/cron-setup-pi5.sh` and usable by hand) posts publicly and always uses the optional loader.

This change set makes that configuration impossible to run by accident: the commands that start the scheduler or the orchestrator refuse it, the existing entry-intent check reports it (so the cron installer refuses too), `bts run` uses the live refusal whenever it is not a dry run, and the example configuration turns the settings on. It does NOT change what "required" means inside the scheduler (ruling R32: forcing it on for DM and public delivery would silently change what hundreds of existing scheduler tests exercise), and it does not touch `bts preview` or the dashboard (change set 5 and later). **Nothing from change set 4a onwards may be deployed before the remaining change sets land.**

## Definitions
- **Effective delivery:** what `bts.scheduler._pick_delivery_mode(config)` returns (`"public"`, `"dm"` or `"private"`), or its `ValueError`.
- **Contest state required:** what `bts.scheduler._contest_state_required(config)` returns today. Its meaning is unchanged.
- **Outward delivery:** effective delivery `"dm"` or `"public"`.

**Known limits, by design (state them in the handover, do not work around them):**
- **The check is at the command, not in the scheduler.** Code that calls `run_day` or `orchestrator.orchestrate` directly bypasses it. The production path is the systemd unit running `bts schedule`.
- **Private delivery with research intent is not checked** and still picks on whatever is on disk. That is the offseason research mode.
- **`bts preview` and the dashboard still use the optional loader.** The preview's pick file can still be delivered without re-selection (change set 5).
- **The box's own configuration file is edited by the operator.** After this change set a box whose file has outward delivery and neither setting will not start its scheduler until the file is fixed: that is the intended failure. The season-start checklist gets a row for it (the lead adds it; do not edit `docs/ops/`).
- **`scripts/cron-setup-pi5.sh` still installs `bts run`** on a decommissioned host; after this change set that command refuses to post without live contest state.
