## Why
A day's pick lives in a file (`<picks_dir>/<date>.json`). Several paths deliver a pick from that file WITHOUT choosing it again: the fallback refresh when the re-prediction fails or returns nothing, the "every candidate game is unavailable" return of `select_pick`, a restart, and the catch-up branch of `bts run`. The delivery step reads the live contest state only to print the streak and to see that a live read succeeds; it does not ask what state the saved pick was chosen on.

Change set 4b-2's reviewers showed what that allows (`build/cs4b2-review/carbon/report.md`, note N2): the 03:00 `bts preview` cron writes the day's pick file using the OPTIONAL loader, so on an opening-stretch morning it can choose a double on last season's streak. If the operator then supplies the day's dated observation (a different streak, a different saver) and the fallback's re-prediction fails, the delivery read succeeds and the preview's pick goes out: a pick chosen on state the live rules refuse. The same hole lets a pick chosen on one dated observation go out after the operator corrected it.

This change set records, on the pick file, the state the pick was chosen on, and makes every live delivery of a saved pick check it. It does not add a way to wake the scheduler or re-run selection on demand (change set 5b), and it does not change selection itself.

## Definitions
- **Live** for a configuration: `_contest_state_required(config)` is true. For `bts run` (not `--dry-run`): always (change set 6a).
- **The chosen-on record** is a new optional field of `DailyPick`, `chosen_on: dict | None = None`, serialised with the pick. When present it is exactly: `{"schema": "bts_pick_chosen_on_v1", "required": <bool>, "kind": "dated" | "automatic" | "legacy_manual" | "model", "streak": <int>, "saver_available": <bool>, "dated": null | {"effective_date": "YYYY-MM-DD", "active_streak": <int>, "best_streak": <int>, "saver_state": "not_earned" | "active" | "used"}}`. `dated` is non-null exactly when `kind` is `"dated"`.
- **The state's identity:** `DecisionStreakState` gains two fields with defaults, `observation_kind: str = "model"` and `dated_identity: dict | None = None`, set by `load_decision_streak_state` from the observation it selected: `"dated"` with the four values above for a dated observation in effect; `"automatic"` when the selected observation is the automatic file; `"legacy_manual"` when it is a manual file that is not a dated observation; `"model"` when there is none. Nothing else about `load_decision_streak_state` changes.
- **A fresh choice:** a `select_pick` call whose result carries a policy decision (`SelectionResult.decision is not None`) and a pick. Returning the existing pick file (locked, unavailable candidates, status failure) is NOT a fresh choice.
- **Matches the live state** (pick, live decision state): the pick has a chosen-on record AND its `required` is true AND one of: (a) the state's `observation_kind` is `"dated"` and the record's `kind` is `"dated"` and the record's `dated` equals the state's `dated_identity`; (b) the state's `observation_kind` is `"automatic"` and the record's `kind` is `"automatic"`. Nothing else matches. Under (b) the streak and the saver are deliberately NOT compared (ruling R33: an automatic reading changes with every fetch, and refusing a saved pick for that would lose picks in ordinary in-season operation; what a supplied observation says is the operator's explicit statement and must match exactly).

**Known limits, by design (state them in the handover, do not work around them):**
- **A refusal here does not choose again.** The pick is re-chosen only by a later scheduled check or a fallback refresh that succeeds. If the re-prediction keeps failing, or no check remains, the day has no pick and the alert says why. A way to force a check is change set 5b.
- **Under an automatic observation the streak and saver the pick was chosen on are not compared** with the current ones (definition (b), ruling R33). A saved pick chosen at streak 5 can be delivered after a fetch has moved the automatic reading to 6, as today.
- **Private delivery and non-live configurations are not checked.** A preview's pick can still be locked locally in private mode.
- **A pick file written before this change set has no record** and is refused for live delivery until it is chosen again. Nothing may be deployed mid-day on a day with an undelivered pick; the build is deployed before the season.
- **The record says what the choice read, not that the choice was right:** `enable` remains the operator's statement.
