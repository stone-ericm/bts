# Blocking findings

**B1 — the new policy call receives unvalidated JSON, so a readable model file can now crash the decision loader.** On 2027-07-15 ET, with no contest observation, `streak.json` containing `{"season":2027,"streak":null}` and `account_state/saver_state.json` containing `{"season":2027,"state":"not_earned"}`, `load_decision_streak_state(..., now=NOW)` raises `TypeError: '<' not supported between instances of 'NoneType' and 'int'` at `src/bts/contest_state.py:364`, inside `src/bts/saver_state.py:33`. The base returns a state. Strings, lists and objects decoded from the streak field reproduce it too; these are file inputs, not hostile Python objects.

This has an observable production consequence: with a real already-posted daily pick, the base loader followed by real `strategy.select_pick` returns that locked pick; the branch fails before selection. See `edge_cases.py` / `base-edges.json` / `branch-edges.json`, family `model-existing-pick`. Both packages used the same actual pick files and selection code.

Smallest sound fix: validate the model streak at the caller before the new helper call (`type(n) is int` and `n >= 0`), report invalid values through the existing model-corruption/`ContestStateError` path, and retain the helper's no-coercion rule. `_load_model_diagnostics` at line 325 returns the raw field with no validation; its annotation does not establish the new callee's precondition. Missing/unmatched-season files yield integer 0; matching-season objects can yield every JSON value. Corrupt-file diagnostics already have a distinct error path. Do not turn invalid values into invented streak 0.
