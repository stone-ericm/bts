1. **Season boundary (before switch):** Live selection runs only on an explicit manual observation for that contest date until an operator inspects recorded endpoint attempts and enables a season-scoped automatic-counter contract (`season_contract.json`).
2. **In-season stale state (decided by Eric, 2026-11-14: *"i prefer keep picking"*):** On an ordinary in-season day after the switch, when an accepted current-season observation exists (and no unacknowledged restore blocks it) but is behind — due to a failed fetch / old observation age, a late contest settlement, or an ambiguous new response — the system **keeps picking on the last accepted streak**, **sends a `WARN` DM**, and **records on both `DailyPick` and `decision.json` that the pick was made on a stale reading**.
3. **Post-restore & saver continuity:** A restore requires explicit acknowledgment before auto picking resumes, and after a restore or `> 36h` blind fetch gap the Streak Saver is treated as spent (`False`) and never auto-promoted until reconciled.

**Fetch classification & write order (`bts fetch-contest-streak`):**
1. Validate HTTP/auth, account match (`expected_username` and prior `user_id`/`username`), envelope (`isinstance(success, dict)` and `"predictions" in success` and `isinstance(success["predictions"], list)` — absent `predictions` key raises `ContestFetchError`), non-empty `rounds` (`rounds == {}` raises `ContestFetchError`), and `0 <= activeStreak <= seasonBestStreak <= 57`. On failure: append `rejected_error` to `contest_fetch_attempts.jsonl`, update `contest_streak_fetch_status.json` (preserving `last_success_at` / `last_accepted_at`), send throttled `_contest_fetch_alert` DM (`6h` per category), exit `2`.
2. Classify `predictions` rows in strict precedence order: **(i)** `season_contract` missing/false/wrong-season -> `season_contract_unverified` (`recorded_unaccepted`, exit `0`, no failure DM); **(ii)** any settled row (`result in RESOLVED`) maps to `round_date.year != contract.season` or `round_id < contract.verified_round_id_min` -> `prior_or_old_round_rows` (`recorded_unaccepted`); **(iii)** any settled row unmapped -> `unmapped_settled_rows` (`recorded_unaccepted`); **(iv)** any settled row maps to `round_date > et_date` -> `future_settled_rows` (`recorded_unaccepted`); **(v)** `contract.season not in rounds_seasons` -> `rounds_missing_contract_season` (`recorded_unaccepted`); **(vi)** same-contract prior accepted `contest_streak.json` exists and (`best_streak < prior.best_streak` or (`settled_count == 0` and `prior.settled_count > 0`)) -> `regressed_or_cleared_profile` (`recorded_unaccepted`); **(vii)** else `accepted` (`clean_settled` if settled rows exist, `witness_date = max(round_date)`; `clean_ledger_lag` if `settled_count == 0`, `witness_date = None`; `unsettled_prior_count` counts rows with `result not in RESOLVED` and mapped `round_date < et_date`). On **(ii)–(vi)**: keep `contest_streak.json` and `saver_state.json` untouched, append `recorded_unaccepted` attempt, update `contest_streak_fetch_status.json` (`last_unaccepted_at`), send throttled `_contest_fetch_alert(..., category="unaccepted_response")` DM, exit `2`.
3. On **(vii) (`accepted`)**, write in order so a crash never leaves a new accepted streak ahead of an un-updated saver: **(a)** append `contest_fetch_attempts.jsonl` + `contest_ledger.jsonl` (`fsync`); **(b)** if `prior_auto` in `contract.season` had `now - prior_auto.recorded_at > 36h`, persist `continuity_verified = False` on `saver_state.json`, else if `continuity_verified` and `restore_state` reconciled, run `maybe_auto_earn_saver(..., last_attempt_id=attempt_id)`; **(c)** write `contest_streak.json` (`attempt_id`); **(d)** write `contest_streak_fetch_status.json` (`last_accepted_attempt_id = attempt_id`), exit `0`.

## 2. The decision table under R24

**Shared classifier:** `evaluate_decision_state(picks_dir: Path, *, require_contest_state: bool = False, target_date: date | None = None, now: datetime | None = None) -> DecisionEvaluation` in `src/bts/contest_state.py` is the sole classifier called by both `load_decision_streak_state` and `bts.health.contest_state.check`. `target_date` defaults to `now.astimezone(ZoneInfo("America/New_York")).date()`, `target_year = target_date.year`. **No branch reads or counts `data/picks/YYYY-MM-DD.json` files.**

**Saver policy mapping (`policy_saver(streak, saver_record, restore_state, auto_age_gt_36h)`):** Returns `False` whenever `saver_record.state in {"uninitialized", "used"}`, `not saver_record.continuity_verified`, `auto_age_gt_36h`, or `restore_state.saver_reconciled_at is None`. When continuity is verified and reconciled: `"active" -> True`; `"not_earned" -> True` for `0 <= streak <= 9` (future earning value preserved in MDP), `False` for `streak >= 10` (plus `WARN` `saver_not_earned_in_zone` at `10 <= streak <= 15`).

**Alert channels & moments (existing mechanisms):**
- **Refusal DM (`CRITICAL`):** `scheduler._alert_contest_state_failure` -> `dispatch_dm_for_health_alerts` (`data/health_state/health_dm_delivery_status.json`), fired at **`run_day` startup (~10:00 ET, before lineup waits)** and at **pre-cascade check start** (`run_single_check` / `orchestrator.run_and_pick`), with `incident_key = f"contest_state:{code}"` so a new refusal reason same-day always sends a new DM while repeats of the same `code` across checks deduplicate. Also emitted at EOD `run_all_checks` and `08:30` ET next-day `bts day-outcome` (`no_decision`).
- **Actionable `WARN` DM (including stale-pick DMs):** `"contest_state"` added to `ALWAYS_ATTENTION_WARN_SOURCES` in `src/bts/health/attention.py`, each with `incident_key = f"contest_state:{code}"`. Dispatched at **`run_day` startup (~10:00 ET)**, on **stale selection in `run_single_check` / `_deliver_and_lock_pick`**, and at **variable EOD `run_all_checks`** (deduplicated per `incident_key` per ET day via `health_dm_delivery_status.json`).
- **Fetch DM:** `_contest_fetch_alert` (`6h` per-category throttle on `01:10, 02:10, 10:30, 13:30` ET cron).
- **Journal-only (`INFO`):** `log.info` in `bts-scheduler` journal; never DM'd.

## 4. The switch to automatic

Switching from daily manual observations to automatic `contest_streak.json` acceptance is strictly an explicit operator command (`bts season-contract enable`), never inferred from round dates, zero values, or settled counts.

1. **What `bts season-contract status --season YYYY` displays before switching:**
   - Current contract state (`unverified` / `enabled` / `revoked`), `restore_state.json`, and `saver_state.json` (`state`, `continuity_verified`).
   - A chronological table over all `YYYY` dates to date joining: **(a)** recorded `contest_fetch_attempts.jsonl` rows (`attempt_id`, `recorded_at`, `active_streak`, `best_streak`, `settled_count`, `mapped_settled` `[round_id -> round_date: result, player_ids]`, `unmapped_round_ids`, `rounds_seasons`, `rounds_year_min_id`, `classification`); **(b)** manual observations written for those dates; and **(c)** the box's own `data/picks/<date>/decision.json` (`action`, `batter_id`s, `scoreable`), `entry_receipts` (`confirmed` / `no_pick`), and graded results (`hit`/`miss`/`void`). Because `mapped_settled` includes `player_ids` alongside `round_date` and `result`, Eric can see directly whether a row with `roundId=1` is his real `YYYY` entry or a reused 2026 ID (`F2B`), and whether `activeStreak` / `seasonBestStreak` reset and tracked real `YYYY` outcomes.
2. **What `bts season-contract enable --season YYYY --confirm-attempt <attempt_id> --by <who>` checks and refuses (exit `2`):**
   - Refuses unless `YYYY == today_et.year`.
   - Refuses unless `<attempt_id>` is the **latest** HTTP-complete entry in `contest_fetch_attempts.jsonl`, was recorded on `today_et` within the last `12h`, has `http_ok == true`, `has_predictions_key == true`, `predictions_is_list == true`, `0 <= active_streak <= best_streak <= 57`, `YYYY in rounds_seasons`, `rounds_year_min_id is not None`, zero `unmapped_round_ids`, zero settled rows with `round_date.year != YYYY` or `round_date > today_et` or `round_id < rounds_year_min_id`, and **at least one** settled `YYYY` prediction row (`settled_count >= 1`, proving post-settlement `YYYY` profile behavior rather than an empty pre-play payload).
   - Refuses if `restore_state.json` has `streak_acknowledged_at is null` or `saver_reconciled_at is null`, or if `saver_state.json` for `YYYY` is `uninitialized` or has `continuity_verified == false`.
   - On pass: writes `season_contract.json` (`auto_counter_verified: true`, `verified_from_attempt_id`, `verified_round_id_min = attempt.rounds_year_min_id`, `user_id`, `username`) and promotes that confirmed `<attempt_id>` payload into `contest_streak.json` (`bts_contest_streak_auto_v2`) so automatic picking is live immediately without waiting for the next cron fetch.
3. **How the switch is undone:** `bts season-contract revoke --season YYYY --by <who> --reason <text>` sets `auto_counter_verified = false`, `revoked_at`, and `revoked_reason` in `season_contract.json` (preserving `contest_fetch_attempts.jsonl`). Selection immediately reverts to Row R3 (requiring a same-date manual observation) until re-enabled.
