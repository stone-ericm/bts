## 2. Total decision table, saver precedence, and alerts

### 2.1 Classifier signature, input space, and proof of totality (`R25 C6`)
`evaluate_decision_state(picks_dir: Path, *, require_contest_state: bool = False, target_date: date | None = None, now: datetime | None = None, expected_username: str | None = None) -> DecisionEvaluation` returns `(row_id, state: DecisionStreakState | None, error: ContestStateError | None, refusal_code: str | None, stale_reason: str | None, alerts: tuple[Alert, ...], recovery_cmd: str | None)`. `load_decision_streak_state` calls `evaluate_decision_state` and raises `ev.error` if non-null else returns `ev.state`. Let `now_utc = now or datetime.now(timezone.utc)` (requiring `tzinfo is not None` when passed), `D = target_date or now_utc.astimezone(ET).date()`, and `Y = D.year`. Every combination of `(require_contest_state, manual_file, contract_file, auto_file, fetch_status_file, saver_file, model_file)` lands on **exactly one** primary row:

1. **Clock-skew rule (`(-inf, +inf)` -> total):** Let `skew = (recorded_at - now_utc).total_seconds()`. `skew > 300` (`> 5m` future) is invalid (`future_timestamp` -> `R3`). `0 < skew <= 300` clamps `effective_age_sec = 0` and `effective_et_date = min(recorded_et_date, D)`. `skew <= 0` gives `effective_age_sec = -skew >= 0` and `effective_et_date = recorded_et_date`.
2. **Gate 1 — Non-live mode (`require_contest_state == False`: `bts preview`, `bts run --dry-run`, `private` with `contest_state_required=false`):** Evaluated **before** live refusal rows `R1`/`R2`.
   - If `manual` is unreadable/non-UTF-8/bad-JSON/non-object or violates `0..57`/`skew <= 300` -> **`R3`** (`corrupt_manual_state`).
   - Else if `manual` is valid `manual_v3` with `season == Y`, `effective_date == D`, `now_utc <= expires_at` -> **`M0` via `P1`**.
   - Else if `auto` is unreadable/non-UTF-8/bad-JSON/non-object or violates `0..57`/`skew <= 300` -> **`R3`** (`corrupt_or_unverified_auto`).
   - Else if `contract` is valid `verified` for `Y` and `auto` is valid `Y` `auto_v2` (matching `expected_username` when set) -> **`M0` via `P2a`/`P2b`/`P3`** (Gate 4 below).
   - Else (contest files absent, expired/other-date manual, missing/corrupt/unverified/revoked contract, prior-season or legacy `v1`/`v2` contest file) -> read `streak.json` for `season=Y`: if unreadable/non-UTF-8/bad-JSON/non-object -> **`R3m`** (`corrupt_model_fallback`); else -> **`M1`** (`source="model"`, `status="model_only"`, `(0, True)` when `{}` or `streak.get("season") != Y`).
3. **Gate 2 — Live manual check (`require_contest_state == True`; NEVER enters `M1`):**
   - If `manual` is corrupt (non-UTF-8/bad-JSON/non-object/`OSError`), legacy `manual_v1`/`v2`, `effective_date > D`, (`effective_date == D` and `season != Y`), `skew > 300`, or `not (0 <= active_streak <= best_streak <= 57)` -> **`R3`** (`corrupt_manual_state`).
   - Else if `manual` is valid `manual_v3` with `season == Y`, `effective_date == D`, `now_utc <= expires_at` -> **`P1`** immediately (even if `contract`, `auto`, `fetch_status`, or `streak.json` is missing/corrupt/revoked).
   - Else (`manual` absent, or valid prior-date/expired `effective_date < D` or `now_utc > expires_at`) -> ignore `manual`, proceed to Gate 3.
4. **Gate 3 — Live contract & auto structural check (`require_contest_state == True`, `P1` absent):**
   - If `season_contract.json` is unreadable/non-UTF-8/bad-JSON/non-object/invalid schema -> **`R3`** (`corrupt_season_contract`).
   - Else if `season_contract.json` is missing and `contest_streak.json` is missing -> **`R1`** (`missing_contest_state`).
   - Else if `season_contract.json` is missing (with `contest_streak.json` present), `contract.season != Y`, or `contract.status in ("unverified", "revoked")` -> **`R2`** (`season_contract_unverified` or `season_contract_revoked`).
   - Else (`contract` is `verified` for `Y`): if `contest_streak.json` is missing -> **`R1`** (`missing_contest_state`); if `contest_streak.json` is unreadable/non-UTF-8/bad-JSON/non-object, `schema_version != "bts_contest_streak_auto_v2"`, undated, `season != Y`, `username` mismatch, cross-validation failure, `skew > 300`, or `not (0 <= active_streak <= best_streak <= 57)` -> **`R3`** (`corrupt_or_unverified_auto`); else proceed to Gate 4.
5. **Gate 4 — Exhaustive fresh vs stale partition on valid `verified` `Y` `auto_v2`:** Evaluate the 5 stale predicates in **strict priority order** (missing/corrupt optional status/attempt files become stale predicates #1/#2 rather than crashing a valid `auto_v2`):
   1. `newer_attempt_unaccepted:<outcome>` (`contest_fetch_attempts.jsonl` has any entry after `auto.recorded_at` with `outcome != "accepted"`, or a corrupt/unreadable tail) -> **`P2a`**.
   2. `fetch_status_mismatch` (`contest_streak_fetch_status.json` missing, unreadable/corrupt, or `last_accepted_attempt_id != auto.attempt_id`) -> **`P2b`**.
   3. `fetch_error_after_accept` (`fetch_status.last_error_at` parseable and `> auto.recorded_at`) -> **`P2b`**.
   4. `observation_age_or_prior_day` (`effective_et_date < D` or `effective_age_sec > 14 * 3600`) -> **`P2b`**.
   5. `settlement_lag` (`auto.unsettled_prior_count > 0` or (`auto.witness_date is None and auto.best_streak > 0`)) -> **`P2b`**.
   - If `>= 1` predicate holds, `status="stale"` and `stale_reason` is the **lowest-numbered matching predicate** (all matching tags listed in `message`). If **0** predicates hold, return **`P3`** (`status="fresh"`).

### 2.4 Alerts, daemon readiness lifecycle, and dispatcher change (`R25 C7`)
- **Three refusal alert rules:** On contest date `D` (with `>= 1` non-void regular-season game):
  1. **First-seen DM:** Send one `CRITICAL` DM when a refusal (`R1`–`R3`) is first seen on `D` (at wake readiness or any check).
  2. **Last-planned-check reminder DM:** If `D` is still refusing at the **last planned check in `plan_run_times` whose `time_et <= fallback_deadline`** (or at the fallback check itself when `plan_run_times` has no check `<= fallback_deadline`), send **one** reminder `CRITICAL` DM.
  3. **Action-change DM:** Whenever the required operator recovery command changes on `D` (e.g., from `set-contest-streak` to `season-contract enable`, or adding `--reopen-skip`), send a new `CRITICAL` DM immediately.
- **Stale warning rule:** `P2a`/`P2b` sends **at most one** `WARN` attention DM per contest date `D` (`incident_key="contest_state:stale_pick"`), while every check logs the warning and stamps `DailyPick` + `decision.json`.
- **Daemon lifecycle, schedule suppression, & operator window:** Readiness runs at `run_day`'s real wake (`compute_wakeup_time` in `scheduler.py:209`: `earliest_game - check_offset_min - 15m` — pre-dawn ET on Tokyo/London slates, or immediate on mid-day service restart) and before each check/fallback. A wake/check readiness refusal **never raises out of `run_day`** (avoiding `systemd` restart loops): `run_day` dispatches the `C7` DM, skips the expensive SSH cascade for that check, and remains in its check loop so a subsequent `set-contest-streak` or `fetch-contest-streak` automatically unblocks the next planned check. On `0`-game or all-void days, wake readiness, checks, and EOD `health/contest_state` suppress contest-state DMs (matching `day-outcome`'s `no_games`). Next-day `08:30` ET `bts day-outcome` (`cli.py:1637`) is strictly a next-morning generic `no_decision` check. Planning leaves `operator_reserve_min` (default `10m`, Section 3.3) before `T_pick - 5m`; a sent DM is never treated as read.
- **Exact `src/bts/health/alert.py` & `scheduler.py` change (`CS6`):**
  - Refusal builders compute `action_hash8 = sha256(canonical_recovery_cmd.encode()).hexdigest()[:8]` (normalized without dynamic clock/countdown strings) and set `Alert.incident_key = f"contest_state:{refusal_code}:{action_hash8}"` (or `f"contest_state_reminder:{refusal_code}:{action_hash8}"` on the single reminder slot).
  - `dispatch_dm_for_health_alerts` (`src/bts/health/alert.py:167–245`) already deduplicates per ET day via `sent_sources` using `a.incident_key or a.source` (`L200–215`) and resurfaces prior failed sends (`_resurface_note`, `L149`). Adding `"contest_state"` to `ALWAYS_ATTENTION_WARN_SOURCES` (`src/bts/health/attention.py:29`) routes `contest_state:stale_pick`, `D1`, and `D2` through `sent_sources` with zero schema change to `health_dm_delivery_status.json`.

### 3.2 Shared `.selection.lock` check transaction & delivery-time state consistency (`R25 C3`)
`run_locked_check_tx(date: str, picks_dir: Path, step_fn: Callable[[SchedulerState], T], *, lock_wait_sec: float | None = None) -> tuple[T, SchedulerState]` in `src/bts/scheduler.py` (`CS5`) wraps **all five** state-mutating paths: (1) daemon `run_day` check iterations (`L2916`), (2) in-loop fallback (`L2958`), (3) post-loop final fallback (`L3036`, including `sr-lastcheck`), (4) `_write_endofday_skip` (`L806`), and (5) `bts retry-pick`:
1. **Lock:** Acquire `fcntl.flock(LOCK_EX)` on `data/picks/<date>/.selection.lock` (blocking in daemon; polling `LOCK_EX | LOCK_NB` up to `lock_wait_sec` default `30s` in `retry-pick`; never held across `_watchdog_ping_sleep` or result polling).
2. **Reload from disk:** Read `state = load_state(date, picks_dir)` (fresh `SchedulerState` only if absent), `decision = load_decision(date, picks_dir)`, and `daily = load_pick(date, picks_dir)`.
3. **Commit/skip guard:** If `decision` has `scoreable == True` or `daily` has `delivery_attempted == True`, sync `state.pick_locked = True; state.committed_pick_written = bool(decision)` and return without re-running cascades or overwriting `<date>.json` / `decision.json`. If `decision` has `action == "skip"` (`scoreable == False`) and caller did not pass `reopen_skip=True`, return `SKIP_FINALIZED` without mutation.
4. **Delivery-time recheck & provenance:** Inside `_deliver_and_lock_pick` (`scheduler.py:1098`), re-evaluate `load_decision_streak_state(picks_dir, target_date=D, require_contest_state=...)` immediately before transport: if `ContestStateError` raises, abort delivery (`False`); if `(streak, saver_available, best_streak, best_status)` changed since `selection` was computed (during a long cascade or cached-candidate deferral), re-run local `select_pick` on the in-memory `predictions` DataFrame (no SSH cascade) before locking, and stamp the delivery-time `state_status`, `stale_reason`, and `contest_recorded_at` onto both `DailyPick` and `decision.json`.
5. **Write, release, rebind:** Call `save_state(state, picks_dir)` (`fsync` + `os.replace`), release `.selection.lock`, and **rebind `state` in `run_day`** so a sleeping daemon waking after `bts retry-pick` sees `pick_locked=True` from disk and enters result polling without clobbering `scheduler_<date>.json`.

### 3.3 `bts retry-pick`: latest-start arithmetic, projected lineups, `--reopen-skip`, and exit codes (`R25 C2, C3`)
- **Latest-start arithmetic from real budget + reserve:** MLB locks each game at `T_cut(g) = T_game(g) - 5m` (`SUBMISSION_CUTOFF_MIN = 5`, `scheduler.py:55`). Using `B_eff = effective_cascade_budget_min(cfg_cascade_budget_min [default 12], _measured_cascade_durations(state))` (`scheduler.py:488`, cold floor `12m`, self-raising to `ceil(max_recent_sec / 60) + 2`) and `[scheduler].operator_reserve_min` `R_op` (default `10m`), the **planning latest start** against the earliest first pitch `T_pick = min_leg T_game(leg)` among the pick's selected primary and double-down games (including doubleheader game-1/game-2 start times) is:
  `T_latest_start(pick) = T_pick - (5 + B_eff + R_op) min` (`T_pick - 27m` on cold defaults: `5m` cutoff + `12m` cascade + `10m` operator entry reserve).
  *Planning allowance vs hard guard:* `T_latest_start` is a planning allowance, not a runtime guarantee. Pre-cascade, `retry-pick` refuses (`exit 2`) if `D != today_et` or zero playable games satisfy `now < T_game - 5m` (later still-playable games remain eligible when earlier games have started), and prints an explicit reserve warning if `now > max_playable(T_game) - (5 + B_eff + R_op)m`. Post-cascade, `_deliver_and_lock_pick` enforces the hard cutoff `now < T_pick - 5m` (`scheduler.py:1032`) across all selected legs and prints `enter_by_et = T_pick - 5m` and `remaining_entry_min`.
- **Projected-lineup handling (`main` APIs):** Calls `_lock_decision_from_predictions` (`scheduler.py:1322`). When `should_lock` is `False` for an unconfirmed lineup: if `now >= fallback_deadline` (`_fallback_min_with_floor` using `5 + B_eff`, `scheduler.py:510`), calls `plan_fallback_action(sel, date=D, picks_dir=picks_dir, now_utc=now_utc)` (`scheduler.py:546`), locking/delivering on `"lock"` and deferring on `"defer"`; if `now < fallback_deadline`, saves the candidate on `SchedulerState` and exits `4` (`DEFERRED`).
- **Reopening a finalized skip (`--reopen-skip`):** A finalized `decision.json` with `action == "skip"` is reopened **only** when `--reopen-skip` is passed while `>= 1` playable game has `now < T_game - 5m` and `delivery_attempted` is `False`: under `.selection.lock`, `decision.json` moves to `decision.reopened_<utc_ts>.json`, `final_skip_candidate`/`skip_summary` clear on `SchedulerState`, and selection runs. Scoreable commits (`scoreable == True`) and `delivery_attempted == True` markers are **never** reopened (`exit 0` or `exit 6`).
- **Result contract and distinct exit codes (`0` ONLY when a scoreable pick is committed):**
  - `0` (`DELIVERED` or `ALREADY_COMMITTED`): New pick locked and delivered (`dm`/`public`, or `private_locked` in `private` mode), or an existing `scoreable == True` commit was already on disk (prints batter(s), delivery status, and `enter_by_et`).
  - `2` (`REFUSED`): `D != today_et`, `0` enterable games (`now >= T_game - 5m` for all playable games), `ContestStateError` (`R1`–`R3`), or finalized skip without `--reopen-skip`.
  - `3` (`SKIPPED_BY_POLICY`): Cascade ran and policy chose `skip`; updates `SchedulerState` skip candidate (and writes `decision.json` `action="skip"` if no feasible confirmation windows remain); nothing delivered.
  - `4` (`DEFERRED_OR_NO_PREDICTIONS`): Cascade returned empty/failed predictions, or candidate is unconfirmed before `fallback_deadline` / `plan_fallback_action == "defer"`; candidate saved, nothing delivered.
  - `5` (`LOCK_BUSY`): `.selection.lock` held by an active daemon check beyond `--lock-wait-sec`.
  - `6` (`DELIVERY_FAILED_OR_UNCONFIRMED`): Transport (`send_dm`/Bluesky) failed, or prior `delivery_attempted=True` crash marker resolved to `locked_unconfirmed` without re-sending.
  - `--dry-run`: Acquires no write lock, mutates no file, sends no DM/post; runs read-only evaluation and returns `0` iff a live run right now would lock/deliver (`2`/`3`/`4` otherwise).

## 4. The switch to automatic (`R25 C8`)

- **Evidence table (`bts season-contract status --season Y`):** Reads `contest_fetch_attempts.jsonl`, `contest_manual_history.jsonl`, `data/picks/Y-*/decision.json`, and `entry_receipts/` (read-only) to print a chronological join: every manual observation (`effective_date`, `active_streak`, `best_streak`, `saver_state`) beside every fetch attempt (`attempt_id`, `fetched_at`, `raw_active_streak`, `raw_season_best`, mapped `Y` settled rows, prior-season rows, unmapped round IDs, `unsettled_prior_count`, and `outcome`).
- **Operator attestation (`bts season-contract enable --season Y --attempt-id ID [--ignore-dates-before YYYY-MM-DD] [--ignore-rounds-through R]`):** `enable` is an **explicit operator attestation after inspecting `status`**, not an automated settled-count proof. Under `account_state/.state.lock`, it verifies that `ID` exists in `contest_fetch_attempts.jsonl` with `http_ok == True`, `target_season == Y`, matching `expected_username`, `0 <= raw_active_streak <= raw_season_best <= 57`, and zero prior-season mapped rows remaining after applying optional `ignore_dates_before` / `ignore_rounds_through` filters (supporting both Opening Day `0/0` with empty `predictions` and mid-season switches).
- **Write order and crash behavior under `.state.lock`:**
  1. `saver_state.json` (+ `saver_transitions.jsonl`): if `saver_state` is `uninitialized` (and not blocked by `last_revoked_at > updated_at`) and `best < 10`, transition `uninitialized -> not_earned`; if `not_earned` and `best >= 10`, transition `not_earned -> active`; never auto-promote `uninitialized -> active` at `best >= 10` (`R25 C5`).
  2. `contest_streak.json`: write `bts_contest_streak_auto_v2` promoted from attempt `ID` (`fsync` + `os.replace`).
  3. `contest_streak_fetch_status.json`: set `last_accepted_attempt_id = ID`, `last_accepted_at = now_utc` (`fsync` + `os.replace`).
  4. `season_contract.json`: write `status = "verified"`, `verified_at = now_utc`, `verified_by_attempt_id = ID`, and ignore filters **last** (`fsync` + `os.replace`).
  - *Crash state between any two steps:* A crash after step 1, 2, or 3 leaves `season_contract.json` untouched (`unverified` or `revoked`), so live readers deterministically stay in `R2` (or `P1` if today's manual observation is active) and never see an enabled contract with missing/mismatched `auto_v2` or `fetch_status`; re-running `enable` with the same or newer `ID` is idempotent. Once step 4 replaces `season_contract.json`, steps 1–3 are already durable on disk, so readers immediately see a consistent `P3`/`P2b`.
- **Supported vs unsupported endpoint behaviors:**
  - *Supported by automatic contract:* (1) Season-reset `activeStreak`/`seasonBestStreak` with empty `predictions` (`0/0`); (2) overnight/multi-hour settlement lag (`unsettled_prior_count > 0` -> `P2b`); (3) retained prior-season rows in `predictions` once filtered out by attested `ignore_dates_before` / `ignore_rounds_through` while top-level counters reflect `Y`; (4) unmapped `Y` round IDs (`witness_date=None` -> `best_status="untrusted"`, `P2b` when `best > 0`).
  - *Not supported (fetch logs `rejected_invariant`, preserves prior `contest_streak.json`):* (1) MLB carrying prior-season `activeStreak` or `seasonBestStreak` (`> 0` before any `Y` hit) into `Y`; (2) `seasonBestStreak < activeStreak` or `> 57`; (3) `seasonBestStreak` regressing below an already accepted `Y` `best_streak`, or unannounced REST response/counter semantics drift. While any unsupported behavior persists, `season_contract` remains `unverified`/`revoked` and daily `bts set-contest-streak` manual operation continues **without a time bound**.
