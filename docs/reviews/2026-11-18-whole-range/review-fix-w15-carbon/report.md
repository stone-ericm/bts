## Blocking findings
- **B1 — `open_regular` leaks a kernel file descriptor on every directory open, causing `EMFILE` crashes or silent `opp_bullpen_hr_30g = NaN` corruption (`src/bts/probable_pitcher_status.py:35`).**
  - *State & inputs:* A directory (or symlink to directory when `follow_symlinks=True`) at `data/models/probable_pitcher_lookup.json`, `data/raw/<season>/<digits>.json`, `data/models/rejected/probable_pitcher_lookup.<stamp>.<sha12>.json`, or `data/health_state/probable_pitcher_cache/<date>.*.json`, either across repeated runs in long-lived `bts-scheduler` or via numeric `.json` directories before valid feeds in one scan.
  - *Wrong production outcome:* `os.open(path, O_RDONLY | O_NONBLOCK [| O_NOFOLLOW])` succeeds on POSIX directories; `os.fdopen(fd, "rb")` (`FileIO.__init__` with `fd_is_own=0`) raises `IsADirectoryError` without closing `fd`, leaking 1 fd per open (`0` leaked on base `f02e6b9c`). At `RLIMIT_NOFILE`, `scan()` (`src/bts/features/probable_pitcher_cache.py:129`) catches `OSError(EMFILE)` and silently drops valid raw feeds — flipping live `opp_bullpen_hr_30g` from `0.5` to `NaN` with no exception — or active-cache temp creation raises `[Errno 24] Too many open files` where base returned `0.5`.
  - *Smallest fix:* In `open_regular` (`src/bts/probable_pitcher_status.py:35`), bind `fd = os.open(path, flags)` inside `try ... finally: os.close(fd)`, check `stat.S_ISREG(os.fstat(fd).st_mode)` on `fd`, and yield `os.fdopen(fd, "rb", closefd=False)` (matching `src/bts/health/alert.py:121-128`).
  - *Demonstrated:* `probe_item5c_complete_edges.py`, `probe_item5e_verify_fixes.py`, `probe_item5g_base_dir_fd.py`, `probe_item5f_patched_verify.py` (`RLIMIT_NOFILE=64`: 70 calls on HEAD gave 60x `0.5` then 10x silent `NaN` with 61 leaked fds; single call with `10..74.json` dirs gave `0.5` on base vs `EMFILE` on HEAD; patched scratch copy gave 70/70 `0.5` and 0 leaked fds).
- **B2 — `warn()` leaves unflushed bytes in `sys.stderr.buffer` on real broken-pipe `stderr` (`EPIPE`), making completed CLI/cron feature runs exit `120` (`src/bts/features/probable_pitcher_cache.py:28-32`).**
  - *State & inputs:* Any cache incident (`invalid_entries` or `unreadable_cache`) in a standalone Python process (e.g., 03:00 ET cron preview/build in a `&&` chain) whose `stderr` pipe reader has closed (`EPIPE`).
  - *Wrong production outcome:* `print(..., file=sys.stderr)` buffers `b"WARNING: ...\n"` in `io.BufferedWriter` before flushing raises `BrokenPipeError`. `warn()` catches the error, so `compute_all_features` finishes, but `BufferedWriter` keeps the dirty bytes: any later `sys.stderr.flush()` raises `BrokenPipeError` and `Py_FinalizeEx` exits the process with code `120` instead of `0`, aborting downstream `&&` steps (e.g. `sync-to-r2`).
  - *Smallest fix:* In `warn()`, if `isinstance(getattr(getattr(sys.stderr, "buffer", None), "raw", None), io.FileIO)`, `sys.stderr.flush()` then `os.write(raw.fileno(), f"WARNING: {message}\n".encode(sys.stderr.encoding or "utf-8", "replace"))`, else `print(...)`, inside `try / except Exception: pass`.
  - *Demonstrated:* `probe_item5c_complete_edges.py` and `probe_item5f_patched_verify.py` (child `compute_all_features` with closed-reader `os.pipe()` `stderr` printed `FEATURES_OK rows=1` and exited `120` on HEAD vs `0` on patched scratch copy).
