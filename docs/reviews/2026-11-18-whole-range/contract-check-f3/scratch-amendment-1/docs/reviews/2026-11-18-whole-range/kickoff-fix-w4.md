## Today (on `main`)
`run_day`'s in-loop fallback runs only after a check whose RESULT carries a pick (`result["pick_result"].daily`). A check that returns nothing (no predictions, a cascade error, a contest-state refusal, a pick-less skip summary) leaves an earlier check's saved pick on disk with no deadline: the loop sleeps straight to the next planned check. Slice 3: a required-read pick for game 101 (19:10, cutoff 19:05, fallback deadline 18:35) is on disk at 18:20; the 18:25 check returns no predictions; the loop sleeps to the 19:25 check for game 102, whose `run_single_check` archives the pick as `stale_pick_*` (past cutoff). No fallback, no pick DM, no missed-pick DM, no decision. The one-game control (no later check) reaches the post-loop final fallback at 18:35 and delivers the same saved pick even though its refresh also returns nothing. The same strand happens after a same-day restart whose first planned check is after the saved pick's deadline. A4 also showed that `_maybe_alert_missed_pick` (5b, after the loop) reads only the on-disk pick, so it is silent once any guard has archived the candidate, and it can sleep past a later check.

## The class this change set must not add to
**An action taken on a plan or a status the clock has made stale.** W3 stopped twice on it (`STOP-W3.md`): a slow state save after the last plan archived an enterable pick; a re-plan dropped a timely postponed status. W4 puts a wait (to the deadline, to the alert time) and a refresh between a decision and its action, so every action in this change set (sleep, refresh, archive, refusal, send, alert, lock) is taken on a clock sample and durable-file reads made AFTER the last wait or I/O that precedes it, and no I/O other than the action itself sits between that final plan and the action. Rows S1 to S6 below are the cases this rule must still catch.

## Definitions (used exactly)
- **Saved candidate:** the slate's `<date>.json` read through today's `picks.load_pick` (a non-regular path, checked first with `lstat` on the path without following it to a FIFO or device, counts as "no saved candidate" and is left in place; an exception from `load_pick` on a regular file propagates exactly as today's readers propagate it, LW3-4) that has `daily.date == date`, is not delivered (`pick_was_delivered` false), not attempted (`delivery_attempted` false), and whose `submission_cutoff_et(daily)` (the earlier committed slot, picks' one definition) is strictly after a fresh `_now_et()`.
- **Eligible day:** `state.pick_locked` false; `state.committed_pick_written` false; no standing skip (`state.final_skip_candidate is None and state.skip_summary is None`, the same condition under which the post-loop wait sleeps today); `daily_decision.load_decision(date, picks_dir)` returns `None` (a scoreable record, any other record, or an exception from it means NOT eligible: no W4 fallback; today's path runs).
- **Candidate deadline D:** computed exactly as the existing in-loop block computes it for a check's pick: `_earliest_pick_game_et`, `resolve_fallback_deadline_min` (standard, morning, cutoff hour), `effective_cascade_budget_min(cascade_budget_min_cfg, _measured_cascade_durations(state))`, `_fallback_min_with_floor`, then `earliest_game_et - fallback_min`.
- **Candidate identity:** `(daily.date, primary batter_id, primary game_pk, double-down batter_id or None, double-down game_pk or None, earliest_game_et)`.
- **Alert time A:** `earliest_game_et - missed_pick_alert_min`, of the candidate that triggered the W4 fallback.

## Required
1. **One trigger point.** In `run_day`'s main loop, after the existing coalesced-run `continue` and before the existing sleep to run k's target, a new helper `_saved_candidate_fallback(...)` (this name; the author lists its signature in the handover) is called when, and only when: (a) this is the first non-coalesced iteration of this `run_day` invocation (a fresh start or a same-day restart), or the immediately preceding executed check of this invocation returned no pick (`not (result.get("pick_result") and result["pick_result"].daily)`) and did not lock; and (b) the day is eligible and a saved candidate exists; and (c) D is strictly earlier than run k's target; and (d) no W4 fallback has already been attempted in this invocation for this candidate identity. A run scheduled at or before D keeps priority (no trigger). The existing in-loop fallback block after a check that returned a pick, the post-loop final fallback and 5b are NOT edited except as item 6 says; their behaviour is byte-identical in every state where W4 does not trigger (journal, transports, files).
2. **The wait.** If `_now_et() < D` the helper sleeps to D exactly as today's in-loop deadline sleep does (SLEEPING heartbeat with `sleeping_until`, watchdog-fed `_watchdog_ping_sleep`, RUNNING after). If D has passed and the cutoff has not, it acts now.
3. **At wake: re-read, never trust the trigger.** After the wait, the helper samples the clock and re-reads: the saved candidate (same reader rule), the decision record (same rule), `state.pick_locked`, the skip state. Then, in this order: a pick file that is now delivered or attempted goes to `_deliver_and_lock_pick(daily, config, picks_dir, state, date, "fallback")` with NO refresh (today's locked and unknown-outcome branches; nothing is sent); a scoreable record, a lock, a standing skip, or no saved candidate ends the helper with no refresh (run k's `run_single_check` short-circuits handle the day as today); a saved candidate with a DIFFERENT identity ends the helper and the trigger is re-evaluated once for the new candidate at the same point (its own D); `now >= cutoff` ends the helper with no refresh and no send, leaves the file for run k's existing stale archive, and sets the pending missed-pick check (item 5) due now. The helper records its start durably before the refresh (item 7).
4. **The fallback itself is today's refresh path.** With an eligible candidate before its cutoff: the pre-refresh confirmation sync for the games of the remaining non-coalesced runs (`runs[k:]` minus `coalesced`), `_refresh_pick_at_fallback_decision(config, date, daily, early_lock_gap, unavailable_game_pks=_games_past_cutoff(state.games, now))` (a `ContestStateError` gives today's `FALLBACK BLOCKED` line and `_alert_contest_state_failure`, then item 5); today's genuine-pick skip clearing and standing-skip handling (`_refresh_is_genuine_pick`, `_refresh_is_genuine_skip`, `_capture_fallback_skip`; a standing skip delivers nothing and sets no missed-pick check); the post-refresh sync; the measured budget including this refresh's duration; `plan_fallback_action` with every input today's call passes (`remaining_runs` = the same non-coalesced `runs[k:]`). There is no decision reuse on this path (an empty check has none to reuse).
5. **The pending missed-pick check (A4's second bullet).** When the W4 fallback ends without a lock (a contest-state refusal from the refresh, a defer, a `saved_pick_refusal` refusal inside `_deliver_and_lock_pick`, a failed send, or item 3's expired cutoff), the helper sets a pending check at A (due now if A has passed). It does NOT set one after a standing skip, after a lock, or after a late-delivery or all-void refusal by the delivery chokepoint (each recorded in `state.delivery_refusals`; their own CRITICAL suffices, A4). While pending, at the same trigger point before every sleep to a later run whose target is strictly after A, the loop first sleeps to A (same heartbeat rule); checks due at or before A run first. At A it re-reads durable state (clock, decision record, pick file, lock, skip state) and: a scoreable record, a delivered pick or a standing skip clears the check silently; an attempted unconfirmed pick clears it (C2's unknown-outcome alert is that state's alarm); a saved candidate whose earliest game is LATER than the pending one moves the check to that candidate's own A; otherwise it calls today's `_alert_missed_pick(config, daily_or_remembered, mins)` once (text, `missed_pick` source, status file, dispatcher dedup and failed-DM handling unchanged; `mins` from the remembered earliest game; in a non-live configuration the batter named is the on-disk candidate's if present, else the remembered candidate's). A pending check not yet resolved when the loop ends is resolved at 5b, immediately before today's `_maybe_alert_missed_pick` call, by the same rule; today's call then runs unchanged (the dispatcher's same-day dedup prevents a second DM). A viable later check stays scheduled while the alert is pending.
6. **No duplicate at loop exit.** The post-loop final fallback (section 5 of `run_day`) does not start a refresh for a saved candidate whose identity a W4 fallback already attempted in this invocation; it proceeds to 5b. In every other state it is unchanged.
7. **Durable evidence for a restart.** The helper appends ONE entry to `state.fallback_refreshes` and saves state right after the wake re-read and BEFORE the refresh: `{"started", "trigger": "saved_candidate", "identity": [...], "alert_at", "archive": None, "duration_sec": None, "reused_check_cascade": False}`; after the action it fills `finished`, `duration_sec`, `action`, `reason` and, for a defer, `archive` (the archive file name), and saves again. No new top-level `SchedulerState` field (a rollback reads an unknown field as corrupt). `_measured_cascade_durations` already skips `None` durations. On a same-day start, before the loop, `run_day` recovers a pending check from the LAST `saved_candidate` entry carried forward in `fallback_refreshes` whose `alert_at` is set, when the day has no scoreable record, no delivered pick and no standing skip; the name for a non-live message comes from the on-disk candidate, else the entry's `archive` file read through today's reader (an unreadable archive gives `?`, today's placeholder). A start with no candidate and no such entry keeps today's behaviour.
8. **Final plan, then act (the class).** Between the last wait, refresh, sync or state save and each action, the helper samples `_now_et()`, re-runs `plan_fallback_action` with the refresh outcome, confirmations and remaining runs it already holds, and takes the action on that plan with no other I/O in between. The telemetry save of item 7 comes AFTER the action. The archive on a defer is the action; delivery goes through `_deliver_and_lock_pick`, whose own cutoff, void, state and marker guards stand. The helper adds no game-status read of its own; the delivery chokepoint's status read stays the only one.
9. **Clock.** The cutoff is the candidate's absolute `submission_cutoff_et`; every comparison uses a fresh `_now_et()` after the I/O before it. The final contest-state read in `_deliver_and_lock_pick` keeps today's rule (LW3-2 stays ledgered for this path).

## Standing rows (each tested or argued in the handover)
- **Interrupt mid-step** (`KeyboardInterrupt`, `SystemExit`) during the wait, the refresh, between plan and action, and after the attempt marker: before the marker nothing is sent and the candidate stays uncommitted (or archived if the defer completed); after the marker a restart takes today's unknown-outcome recovery without re-sending; a restart re-triggers from durable files only (item 7), never from in-memory state.
- **Malformed or non-regular file** at the trigger read, the wake re-read, the alert re-read and the archive read: the definitions' reader rule; evidence left in place; no send.
- **Midnight ET and the year boundary** during the wait or the alert wait (a late west-coast game): absolute cutoff; `daily.date == date`; the pending check belongs to the slate date only.
- **A failed or unconfirmed send:** today's handling inside `_deliver_and_lock_pick`; a failed send sets the pending check (H10); an unconfirmed one is C2's.
- **A restart mid-step:** H4, H5, the interrupt row.
