## Replacement texts

**Items 1–2 and “What the base accepts and this refuses”**

- “One new read … `wrong_game` changes the outcome” → “On `(True, 'match')`, use the exact saved selection and four responses. Build candidate rows from both sources, using the verifier's integer normalization for round and player IDs, and a single bounded capture inventory. A candidate is usable for a game comparison only when its unit has one non-null positive integer game binding, agrees with the row's round, and has no conflicting non-null game or round across the inventory. The receipt's existing slot qualification still uses its own typed rows and assignment rules.”
- “Exactly the runs … whatever the other leg's state” → “A batter match becomes nonterminal only for one of four reasons: (a) at least one batter group has valid positive integer saved game IDs and a nonempty set of candidate rows whose usable game bindings cannot cover all that group's distinct required `(batter, game)` slots one-to-one, with every candidate bound in the target round; (b) a saved slot lacks a valid game ID; (c) the inventory fails validation or its read budget; or (d) a prior unresolved game warning exists and full current game coverage is still unproved. Use `wrong_game` for (a) when a candidate names a game outside that batter's saved set. If all candidates are in the saved set, identify the uncovered leg and use `game_check_unavailable`, as in (b)–(d). Exit 1 and keep these states retryable. Shared-batter legs each require a row for their own game. Preserve a correctly bound leg. Do not infer a game from a round conflict, unknown binding, or ambiguous row whose game could satisfy the missing slot. An exact duplicate saved `(batter, game)` stays unsupported. On other first matches retain the base batter-only acceptance, including well-formed absent or unbound capture evidence.”
- N4/N9/N10/N11 → “An initial batter-only match may still confirm with absent or unbound evidence as specified above. A double with evidence covering both distinct slots confirms. After an unresolved game warning, require a current, in-time binding for all slots before an all-clear. EOD health reports WARN for `alerted` and CRITICAL for `dm_failed`, with the marker's reason, once the window is closed.”

**Item 3, affected N/M rows and restart**

- “Sending it consumes `wrong_game` and `initial` …” → “Maintain `initial`/`t30`/`t15` for absence or batter mismatch and `wrong_game`/`wrong_game_t30`/`wrong_game_t15` for game conflicts, with `game_check_unavailable` as a one-time verification-gap warning. The first warning of each kind is due immediately while in the window, independent of the other kinds. A successful send consumes its own due tiers, including already crossed reminders; failures and missing recipients leave the new tiers retryable. After a conflict, actual absence or mismatch uses its own base ladder. Keep every prior tier across observations and failures.”
- “A failed first wrong-game DM follows the base's failed-DM rules …” → “Record whether a warning was delivered, separately from current observation and remaining tiers. Keep `dm_failed` when the first warning failed and no warning succeeded, including a later run that crosses cutoff. After cutoff log the observation and skip sending. Attempt the all-clear only after current in-time proof of all slots and a delivered warning. Keep an all-clear pending after a failed send, and retry only on a fresh in-time proof. Delivery with a lost acknowledgement or interruption before the marker can repeat. With no prior game warning, the base ladder and all-clear rules apply.”
