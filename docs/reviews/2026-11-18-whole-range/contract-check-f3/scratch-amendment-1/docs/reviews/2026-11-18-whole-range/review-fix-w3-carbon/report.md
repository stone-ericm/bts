# Review Report — Change Set W3 (`f7a8f601` + `59b72c04-save-hook.patch` vs `ceab9854`)

## Verdict
**BLOCK** — One production refusal-ordering regression on reused candidates causes postponed/cancelled games past the submission cutoff to page `[late_delivery]` naming the batter instead of `[postponed_pick]`.

## Blocking findings

### B1. Reused candidate on a postponed/cancelled game at or past `cutoff` skips the void-game guard and pages `[late_delivery]` naming the batter
- **File & line:** `src/bts/scheduler.py:3517-3527` on `59b72c04` (`src/bts/scheduler.py:3514-3524` on `f7a8f601`).
- **Concrete state & inputs:**
  1. **Reuse `deliver` path:** 1-game slate `2027-03-24`, Game `101` scheduled `19:10 ET` (`cutoff = 19:05:00 ET`), `dated(0)` contest state. The `18:25 ET` check selects Batter `101` (`0.99`, projected), overruns to `19:05:30 ET`, and Game `101` is `Postponed` (`statusCode="PO"`). `plan.action == "deliver"` (`no_feasible_window`), `defer_void_games == {}`.
  2. **Reuse `defer` path:** 2-game slate (`Game 101` `19:10 ET`, `Game 102` `19:20 ET` with `18:50 ET` check), `dated(30, best=30)`. The `18:25 ET` check finishes at `19:04:56 ET` (`>3s` before `19:05:00 ET`) with projected single Batter `101` while Game `101` is `Postponed`; `_replan_after_reuse_poll` records `defer_void_games = {101: "Postponed"}` and `save_state` at line `3516` crosses `19:05:00 ET`.
- **Wrong outcome:** `if reused_check_cascade:` runs outside `if plan.action == "defer":` and checks `if now >= cutoff:` before `defer_void_games` and before `_deliver_and_lock_pick` (which checks `_void_committed_games` at `1368` before `now >= cutoff` at `1380`). Both paths record `delivery_refusals` with `reason="past_submission_cutoff"` instead of `"game_not_playable"` and send CRITICAL `[late_delivery]` (`"LATE DELIVERY REFUSED: Synthetic Batter 101 would have been sent ..."`), naming the batter on a postponed game in violation of the L03 postponed-pick rule (`scheduler.py:2655-2656`), contract Version 2 item 6, M8, and Check 2. On `ceab9854`, both cases emit `[postponed_pick]` without naming the batter.
- **Smallest fix:** Gate `src/bts/scheduler.py:3517-3527` on `if reused_check_cascade and plan.action == "defer":` and move the `if defer_void_games and len(defer_void_games) == len(_committed_pick_game_pks(daily)):` block ahead of `now = _now_et(); if now >= cutoff:`. (`deliver` then reaches `_deliver_and_lock_pick`'s normal void-before-cutoff guard; an already-expired `defer` skips polling so `defer_void_games` is `{}` and still takes `_refuse_late_delivery`.)
- **How demonstrated:** Reproduced on `f7a8f601` (`probe_2_adversarial_and_parity.py` -> `probe_2_results.json`), on `59b72c04` (`probe_8b_verify_59b72c04.py` -> `probe_8_59b72c04.json`), and under the real shipped MDP policy with the 2-line fix verified (`probe_6_real_mdp_controls.py` `head_fixed_void_order` -> `probe_6_results.json`).

## 1. The class of the original defect
Tested candidate swaps after `save_pick`, recursive replacements inside `append_lineup_evolution`, `save_pick` wrappers (`deepcopy`, in-place second save, no-op), trailing-whitespace edits, Warmup-cached selections, slept fallbacks, cross-check carry-over, mid-step restarts, scoreable `decision.json` arrival, `delivery_attempted=True` arrival, standing MDP skips, dated contest-state corrections, and midnight rollovers (`probe_1`, `probe_4`, `probe_6`, `probe_8b`). Aside from **B1** (where reuse past `cutoff` on a postponed game emits `[late_delivery]` instead of `[postponed_pick]`), no sequence caused reuse to apply a decision to a different pick, send a different batter than committed, reuse after sleep/across checks/after restart, or send where a second cascade would have refused (subject to the ledgered accepted cost that reuse does not run a new cascade).

## 2. Nothing that worked before is lost
Compared `ceab9854` vs `HEAD`/`59b72c04` across 14 non-reuse scenarios covering direct `_deliver_and_lock_pick` callers (`lineup`, slept `fallback`, `final fallback` across `dm`/`public`/`private`), post-loop sleep+refresh, missed-pick alert, unknown-outcome alert, late/void refusals, 4c warning, and result polling/scoring (`probe_3_parity.json`: 14/14 byte-identical).
- **Days ending with no pick and no alert that `ceab9854` would have alerted:** Demonstrated two concrete 2-game (`19:10 ET` + `20:10 ET`) scenarios: (1) **Race-free projected deferral (`probe_7_results.json` `race_free_two_game_silent_day`):** `dated(30, best=30)`, `18:25` check overruns to `19:00` with projected single Batter `101`, later cascades take `6 min` and return `None`; `ceab9854`'s failed `19:00` refresh loses `block_reason` (`should_post=None` -> `deliver`), crosses `19:05` cutoff, and pages `[late_delivery]`, whereas `59b72c04` reuses `block_reason="primary_projected"` -> defers (contract item 5), unlinking `<date>.json`, and W4 (ledgered A4) leaves 0 picks and 0 alerts when `19:25` returns `None`. (2) **Abandoned reuse (`probe_2_results.json` `item2_two_game_abandoned_reuse_loses_both_contest_and_missed_alerts`):** `<date>.json` gains `b"\n"` and `best` changes to `1` before the post-poll reload (`scheduler.py:3508` `continue`), skipping `ceab9854`'s `[contest_state]` page while `19:25` archives `<date>.json` as `stale_pick` (`0` picks, `0` alerts).

## 3. The new lookups
Probed `_reuse_lookups` and `_replan_after_reuse_poll` (`probe_1_results.json`, `probe_4_replays.json`): a `1.2s` confirmation + `1.5s` status call finished in `2.005s` wall-clock under one shared `2.0s` monotonic deadline; partial confirmations (`{102: {"away"}}` fast, `103` hanging `3.0s`) were retained while failing/timed-out workers were ignored; polling was skipped completely when `cutoff - now <= 3s`; a daemon worker finishing after the deadline pushed only into the unreferenced local `completed` queue and left `confirmed_sides` untouched; and `planner_inputs` on reuse filtered `coalesced` runs without adding `0.0s` to measured cascade durations.
