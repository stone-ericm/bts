- **NOTE — order and limits.** The Bash model passes recovery-first/late SSH on the same boot, same-SHA re-run with a new attempt, owner dies during phase 2, owner commits despite lost status, later commit before older recovery, and contention without service writes. It fails v2's handoff: B can take over an uncontained A, die on TERM before its trap, and make A's delayed recovery skip. Arm before publication to handle that TERM. Two lost owners can still leave an unowned candidate. If recovery never gets to record a mark (or the host reboots and loses it), an older SSH request that first reaches the box late can take ownership after a newer run, if the action/runner permits that order. GitHub concurrency alone supplies no on-box evidence. The shim model does not establish that the action retries this way. Carry that explicitly in L2/L9. A stronger guarantee needs excluded scope and can cost a play or manual containment.
