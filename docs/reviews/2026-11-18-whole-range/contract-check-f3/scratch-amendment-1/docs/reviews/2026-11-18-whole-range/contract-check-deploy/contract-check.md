# NOT YET

**MUST FIX — smallest design change.** Use a persistent, host-owned deployment hold that is armed before the reset and survives SSH loss and reboot. It must fence boot and roll-forward recovery, stop the scheduler and dashboard on failure, and keep installed candidate-code cron and one-shots from running until a successful deploy. Keep a stock-Python/system-curl monitor outside the checkout and project venv, keyed to the same hold. An SSH shell's `stop` plus a writable heartbeat cannot provide these guarantees. This changes D2–D5 and the host bootstrap, so settle the transaction and recovery design before building.
