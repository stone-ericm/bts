- **NOTE — Why the bits can match.** For a team's chronologically sorted rates `r[0], r[1], …`, row `i` of `shift(1).rolling(30, min_periods=10).mean()` uses `r[max(0,i-30):i]`. The unshifted rolling result at reliever row `i−1` evaluates the same sequence in the same order. The leading shifted `NaN` adds/removes no observation or arithmetic term. A strict predecessor lookup therefore gives the same bits on existing values and evaluates through the predecessor at gaps. The corrected reindex route runs the original shifted calculation with one terminal placeholder and carries each result from its effective date, preserving undefined results. Literal forward-fill of shifted values uses the prior reliever's *stored* value. It preserved all valued 2025 rows, yet was stale at 29 gaps (max 0.01578947), missed a first eligible gap in a synthetic case, and carried stale numbers across undefined windows.
