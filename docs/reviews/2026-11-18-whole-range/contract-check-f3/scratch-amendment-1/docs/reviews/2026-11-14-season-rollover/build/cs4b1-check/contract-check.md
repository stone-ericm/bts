**4b-2 remains buildable (NOTE).** Valid automatic switch Y + parsed exact auto_v2 with season Y and equal identifier is a complete acceptance predicate. Re-enable after revoked/corrupt/other_season generates a new identifier, so old/restored observation alone cannot pass; no-op retains the generation. No fetch identifier needs adding to the switch and fetch must not update it. A fetch failure before replacing the observation leaves the mismatch; a failure after observation replacement can leave matching state despite nonzero command exit, as row 5 expressly permits. The barrier is replacement, not successful completion of all four stages.
Revoked already requires a valid identifier, allows null switched_at and requires revoked_at. A later revoke can retain the prior wholly valid same-Y identifier/switched_at, or generate a fresh tombstone UUID with null switched_at for absent/corrupt/other-season input; neither can authorize an observation while revoked. Its construction policy belongs to 4b-2 and needs no format migration. This half already requires other_season enable to replace with fresh Y/id and null revoked_at, and carry revoked_at only from a wholly valid same-Y snapshot; no timestamp ordering/monotonicity should be inferred. Restoring an entire matching switch/observation pair without revoke remains undetectable; R30's quiescence/runbook decision addresses operator recovery.

**Additional operator traps (NOTE, not new design blockers).** The retained account guard now blocks even ledger/status-only success: a different account in the frozen automatic file prevents inspecting the new account through this fetch, and enable does not repair it; malformed prior nonobject/UTF-8 can still fail without DM. `status` shows ledger history but not the fetch-status file's last failure: its newest visible row may predate a rejected/failed attempt. Ledger success or an equal identifier displayed beside revoked/other-season state is not live acceptance, and mixed-year settled counts prove row coverage, not which season the counters describe.
Unswitched rows still feed the dashboard's two-read saver nudge and analysis consumers: they can show fresh-looking evidence beside an unchanged flag/automatic observation. First switched fetch at best≥10 with a cold flag does not initialize it active; a dated observation's saver does not transfer to the flag. These follow existing helpers/CS4a, not an absent 4b-2 feature. Do not deploy this half: the missing live gate, ageing frozen files, operator attestation, successful-only ledger, and no-lock races are already named limits and are NOT MUST FIX findings.
