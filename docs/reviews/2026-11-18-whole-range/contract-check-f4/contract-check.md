## 3. The design

I searched the app, tests and scripts for `DayOutcome`, its serialization and each model streak reader. Only `classify_day` constructs it in application code; the appended default preserves the four-argument call. The CLI delegates JSON, exit and DM to this object. No other production reader of `as_dict()` or its stdout surfaced. Model diagnostics, health, save/replay, shadow/strategy, dashboard, export/verify and restore checks have different acceptance rules and need no behavior change. In particular, health flags missing counts/files, while scoring can start from zero.

`probe_outcomes.py` compared all 15 base day states with scratch. The good-file results match after projecting away the new key. For `[]`, clean-state heads change and existing problem heads and details survive. But 5,000 digits changed `NO DECISION` into exit 2 with no JSON and `THE CHECK COULD NOT RUN`; 12,000 levels changed it into a traceback path without the alert. Read and decode failures must be contained in the new read, after day classification. An independent bad config still exits 2, with the same DM.

Nightly grading and reconcile stop until it is repaired, so results are not being scored. If a health CRITICAL also arrives, both messages need triage.

Interrupting the real scorer before `os.replace` left the old bytes readable. An interruption after replacement and before saving the pick can leave inconsistent records with a readable streak. An externally truncated file did produce the notice. At New Year and a simulated next-season opening, a valid prior-season file was quiet and the new season loaded zero. A string count with that same tag triggered the notice although the new season still loaded zero. Preserve the file in place during triage and use B8b(2) for supervised recovery. The notice should describe evidence, which jobs may be affected and where to take it, without declaring a halt or inviting a repair after the cutoff.

## 6. Other changes and sequences

An oversized integer or overly deep JSON can hide a pre-existing `NO DECISION` or other problem alert as above. On a skip/off day, or with a tolerated count or successful replay, v1 can falsely say grading stopped. If a complete replay replaces yesterday's bad file before 08:30, the morning view is clean while earlier failure evidence remains in the logs. This is a snapshot limit. The helper avoids a FIFO read when it can open and identify the descriptor, but reads a regular file to EOF and can stall on a growing file or slow filesystem. In the 15-state comparison every file's contents were unchanged; the morning command did not write picks, decisions, streaks or health state. The existing DM is its outward effect.
