## The defect
A restart between the attempt marker (`delivery_attempted=True` saved on the pick) and the confirmed send reaches the classification-lock branch of `run_day`, which locks the day `locked_unconfirmed` and journals one line, but never sends the `DELIVERY OUTCOME UNKNOWN` CRITICAL that `_deliver_and_lock_pick` sends for the same state. The day can pass with no DM (the entry watchdog, if it runs, and the 08:30 `bts day-outcome` are the only later signals). Separately, the existing alert shares `CRITICAL:late_delivery` and the shared status file `health_dm_delivery_status.json` with the cutoff refusal, so either can suppress the other on one ET day, and the dispatcher records `sent` even when the transport returned no message id.
