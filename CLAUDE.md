## Work policies (adopted from the EoR project, Eric 2026-11-12: "Update all our work policies to match those developed in the eor project")
Source, mapping and what this supersedes: `docs/superpowers/notes/work-policies-2026-11-12.md`. Roadmap: `docs/superpowers/plans/2026-11-12-2027-season-roadmap.md`.
- **Review by tier.** A mixed change takes its highest tier.
  - **A, pick-path behaviour** (pick choice, delivery, entry, streak/saver state, scheduler timing, policies): RED-first tests, the gate run, a real-artifact check, and ONE fresh Codex review of behaviour, at most two rounds.
  - **B, captures and instrumentation:** tests, the gate run, a real-artifact check. No review. Write each capture's limits beside it.
  - **C, tools that decide acceptance** (study runners, scorers, the launcher): RED to GREEN on real excerpts, and run the tool end to end on the real input before handing over. Review only for the one tool that decides a commit or a result. Mutant ledgers live here only.
  - **D, tests, docs, records:** no review.
- **The gate run** is the commit test: the focused tests for the change, then the fast suite (Quick Start), plus a fixture-day dry run for pick-path changes once it exists. Green means commit and push `origin main`. No per-launch custody steps (sealed outcomes, tuple checks, markers, heads-up messages).
- **A test-code or evidence-tooling finding is a NOTE, never a BLOCK,** unless it makes a false claim about behaviour that no gate run or real-artifact check covers. Reviewer prompts name the tier and say so.
- **Three BLOCKs stop the session, never the work:** record the obligations, write a kickoff brief, start fresh and change something material.
- **Additions from the 2026-11-18 workflow review (lead, ruling R43; `docs/audit/2026-11-18-workflow-review/`; Eric can overrule):**
  - **A change that silences an alarm or loosens a verifier is tier A**, one piece per change set, with a contract check and a "must still catch" table written BEFORE an author starts (the F4 to F8 batch cost four BLOCKs for one merged cron flag).
  - **Every tier A contract carries standing hostile-input rows:** an interrupt mid-step, a malformed or non-regular file, midnight ET and the year boundary, a failed or unconfirmed send, a restart mid-step. Round-1 BLOCKs kept landing on these.
  - **Independent pieces merge independently:** a clean piece of a batch lands when it is clean.
  - **From the 2026-11-20 workflow review (ruling R51; `docs/audit/2026-11-20-workflow-review/`):** the lead does NOT override a second-round BLOCK (what lands next is a materially revised scope with a fresh verdict on the changed material, or Eric's recorded acceptance); **text shown to the operator** (checklist rows, alert wording, printed commands) is reviewed with the change it belongs to, each sentence checked for "what if he does exactly this in the worst state"; every archived review records what it ran and what it did not; a delegated Claude session is listed in `~/bts-runs/watched-sessions.txt` for the standing watcher (`~/bts-runs/watch_sessions.sh`: it answers the known read prompt and messages `bts-lead` when a session is stuck on a dialog, or idle or done for more than 30 minutes: a dropped API connection left one idle and unseen for 22 hours on 11-23; keep only sessions with work in progress on the list) because one sat on a permission prompt for 13 hours on 11-19; after a machine restart check that the lead's herdr agent name is still `bts-lead` (it came back under another name on 11-20) and restart the watcher and the backtest runner by hand; the closing test before any deploy is the four slice harnesses re-run, one blind read of the final head, Carbon on slices 2 and 3, and a walk of every season date through the decision path.
  - **Scope is frozen at tag `review-candidate-2026-11-18`** until the whole-range review (three slices by scenario, `docs/reviews/2026-11-18-whole-range/`) is done: no discovery lane and no fix enters `main`'s `src/` unless that review asks for it; new findings go to the ledger.
- **Review cadence (Eric 2026-11-14: "let's make sure these types of reviews are more frequent going forward", about adversarial reviews by another agent; this replaces the draft sprint's single review before the opener):**
  - **Tier A:** a fresh adversarial Codex review of each change set **the day it is written, before it is pushed**. Not batched across days.
  - **Tiers B and C:** everything that changed is in a **daily adversarial Codex batch review** (one round), besides the pre-result review of any result-deciding tool. "No review" above now means no review of its own.
  - **Before the pre-season deploy:** still one whole-range review, by a reviewer that has seen none of the earlier rounds.
  - **Every review is adversarial:** the brief says to assume the author is wrong, asks for concrete counterexamples run against the real code, and asks for false greens. The reviewer's probes are adopted as regression tests. Codex reviewers run the best model at the highest reasoning effort (`-c model_reasoning_effort=xhigh`), memories off.
  - **A second model family reviews tier A in parallel** (decided 2026-11-14 after two known-answer tests of Hydrogen, `docs/audit/2026-11-14-gemini-known-answer-tests.md`, and a third of Carbon after the subscription moved to AI Ultra, `docs/audit/2026-11-14-gemini-carbon-known-answer.md`, ruling R22): **Gemini 4 Carbon at High via `agy --model gemini-4-carbon-high`** (Hydrogen XHigh, `gemini-4-hydrogen-xhigh`, when Carbon's allowance is short), in an isolated copy cloned from a bundle of the commit under review, with the Codex brief plus "write and run your own adversarial probes". Codex's verdict is the gate; reproduce every Gemini finding before acting on it. Check `/config` first: Enable Telemetry and Use AI Credits must read off.
  - Design questions are still decided by the lead without design-review rounds; it is the CODE that is reviewed more often.
- **Design authority:** the lead session decides design questions, ledgers them with cost if wrong, and reports daily; Eric can overrule afterwards.
- **Owner-only:** spending (including restoring the box), any deploy to the box, anything on the real contest account, delivery mode, reading 2027 outcomes for a study with no exposure-register row, cutting scope, publication.
- **In season** (my adaptation; EoR's basis was that nothing is published): tier A changes are hotfixes from a clean branch at the deployed commit, reviewed once before deploy; new captures get a failure-direction check on the box in their first week.
- **Unchanged:** every Safety Rule below, the exposure register and pre-registration (Eric's D2), test first, failure-direction verification, the frozen 2026 artifacts.
- **Agents:** Codex lanes and reviewers with memories off and Remote Control off; check `ai-usage` before staffing; long runs go remote, not on the Mac. When agent work spans more than a day, run the daily multi-model workflow review with a delivery estimate.
